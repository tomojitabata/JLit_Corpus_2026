# 開発記録 — この教材を作る過程で起きたこと

**これは受講生向けの記述ではなく，コースウェア開発に際して生じたこと，
気がついたこと，などを備忘録としてまとめたものである。**
用語集（`glossary.md`）は受講生が読むものなので，事故の経緯や日付入りの
改訂記録はそちらに置かず，ここにまとめる。用語集には**規則だけ**が残る。

残す理由は二つある。ひとつは，同じ失敗を二度繰り返さないため。実際に
`03b_merge_volumes.py` では同じ形の失敗が二度起きている。もうひとつは，
検査スクリプト（`check_*.py`）が**なぜ存在するのか**を説明するため。
どの検査も，ここに書かれた事故のあとで足されたものである。

共通しているのは，**どの事故でもエラーが出なかった**ことである。件数は合い，
図は描かれ，処理は最後まで通るので，結果が誤っていても人の目では気づけない。
そこで，誤りを自動で見つける検査スクリプトを，事故のたびに書き足してきた。

## 2026-09-22　（用語集の「`work_rows()` / `work_labels()` ★」に関わる）

`corpus_metadata_v3.csv` は，v1 由来の行では作品 ID が 0 埋めされておらず
（`1743`），増補した行では 0 埋めされている（`001504`）という**混在状態**
にあった。`07_descriptive_stats.py` だけが素朴に
`f'{pid}_{wid}'` で照合キーを作っていたため，**101 点のうち 62 点が突合できず**，

- `pca_coordinates.csv` の `year_first` と `period` が 62 点で空になり，
  PCA の図に「**初出年不明（62）**」と灰色で並んだ
- `work_profile.csv` の `period` も空になった
- `keyness_by_period.csv` に `unknown` という**架空の時代**ができ，
  その 62 点が「時代のキーワード」の計算に混ざった（参照コーパス＝残り全部にも
  入るので，**他のすべての時代の G² が静かにずれた**）

**エラーは1つも出ていない。** 数字は出るし図も描ける。図の凡例に
出た件数がメタデータと合わないことに気づいて初めて分かった。

直したこと: (1) 07 の照合キーを `stem_keys()` に集約して 0 埋めを含む全綴りを
登録，(2) **突合できなかった件数を必ず報告**し，1割を超えたら停止
（`--allow-unmatched` で続行可），(3) period が無い作品は時代別集計から
外す（`unknown` を作らない）＋参照コーパスも同じ母集団で数える，
(4) `00_extend_metadata.py` が ID を6桁に揃えて書き出す，
(5) `attach_meta()` が**空のセルも**補って件数を報告，
(6) `check_stem_keys.py` で 0 埋め忘れを静的に検出。

**教訓は「照合キー（作品の ID）をその場で作らない」である。** 必ず
`work_rows()` か `stem_keys()` で作る。そして**突き合わせで一致した件数を
必ず数えて出す**。
数えていない照合は，失敗しても気づけない。

## 2026-09-26　（用語集の「分冊結合 (`03b_merge_volumes.py`) ★」に関わる）

**2026-09-26 の事故。** README の再構築の連鎖に `03b` が入っていなかった。
その結果『夜明け前』は第一部上（12 万語）だけ，『家』は上巻（7.6 万語）
だけが集計に入り，**島崎藤村の 43 万語がどの集計にも入っていなかった**。
巻別の行は `completeness=merged` で集計から外れるので，**誰も文句を
言わない**。メタデータの側は「結合済み」と宣言していたのに，本文は
結合されていなかった——この食い違いが発見を遅らせた。

悪いことに『家』には v1 の合本行が無く，**全体の語数がどこにも現れない**
まま、16 万語の作品が 7.6 万語として数えられていた。

手当ては3つ。(1) README と `docs/corpus_design.md` の連鎖に `03b` を入れた。
(2) **`04_normalise.py` が，巻別 XML が残っていれば止まる**ようにした
（`--allow-unmerged` で続行できる）。(3) `00_extend_metadata.py` は以前から
「`merged` の行に実測値がある」と警告していた——この警告が今回の発見の端緒
である。**手順書を直すだけでは足りない。検査スクリプトに見張らせる。**

## 2026-09-27　（用語集の「分冊結合 (`03b_merge_volumes.py`) ★」に関わる）

**2026-09-27 の事故（同じ工程で二度目）。** 外字がすべて解決したはずの回で、
島崎藤村『家』にだけ `〓` が8箇所残った。`03` の報告は全ファイル「未解決 0」
である。原因は **`03b` が `charDecl` を結合していなかった**こと。`03` は
巻ごとに `<g ref="#id"/>` を書き、字形の定義も巻ごとに `teiHeader` へ置く。
`03b` は本文と `sourceDesc`・`publicationStmt` は引き継いでいたが、
**定義だけが落ちた**。下巻にしか出ない屋号記号「ヤマにナ」8箇所が定義を
失い、`04` が `〓` に落とした。

教訓は前回と同じ形をしている。**本文を結合するときは、本文が参照している
ものも一緒に結合しなければならない。** `<g ref="#id"/>` は本文の中の
ポインタであって、指す先が別の場所にある。手当てとして `03b` は各巻の
`charDecl` を `xml:id` で重複排除しながら統合し、足した数を
`字形定義 +N` として報告するようにした。

気づけたのは `04` が作品ごとに「未解決外字」を数えているからである。
**合計だけを見ていたら気づかなかった。** `03` の合計は 0 だったのだから。

## 2026-09-27　（用語集の「`completeness` の値」に関わる）

**2026-09-27。** 外字がすべて解決し `03b` も直った回でも
`99_validate.py` の FATAL が2件残った。江戸川乱歩『灰色の巨人』
（`DUPLICATE`：本文が『魔法博士』と同一）と島崎藤村『家（下）』
（`PARTIAL`：上巻欠落）である。どちらも **v3 では `complete` と `merged`
に直っている**。README の連鎖が `v2` を渡していたのは，`v2` しか
メタデータが無かった頃の名残であった。

正しい対応は次のとおり。v1 の診断には `v2`（変数名も `META_V1`）、
再構築後の検証・記述統計・作図には `v3`。`00_extend_metadata.py` は
`v2` を**入力**として読み `v3` を**出力**するので，そこだけは `v2` のまま。
