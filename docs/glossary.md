# 用語・概念集 — 近代日本文学コーパスの構築と計量分析

**対象**: 本授業（全8 Step）の受講生
**使い方**: Step ごとに独立して読める。予習では「キーワード」だけを見て
自分で説明を試み，復習では「確認問題」を解く。

---

## この冊子の使い方

### 予習（Step の前に15分）

各 Step の冒頭に **キーワード** を並べてある。まず**そこだけを見て，
一つずつ自分の言葉で説明してみる**こと。説明できない語に印をつけ，
その語の項目だけを読む。全部読む必要はない。

思い出そうとしてから読むほうが，読んでから思い出すより定着する。
順序を逆にしないこと。

### 復習（Step の後に15分）

各 Step の末尾に **確認問題** がある。解答は折りたたんであるので，
**必ず自分の答えを書いてから開く**こと。問題は「用語の意味」ではなく
「なぜそうするのか」を問う形にしてある。授業で測っているのは
用語を知っているかではなく，手続きの理由を言えるかである。

### 記号

| 記号 | 意味 |
|---|---|
| ★ | その Step の中核概念。ここが分からないと次へ進めない |
| ⚠ | **誤解が起きやすい語**。取り違えると結果が静かに狂う |
| `code` | スクリプトの引数・列名・ファイル名。そのまま打てば動く |

### 用語の三層

本授業の用語は三つの層に分かれる。混ぜないこと。

| 層 | 例 | 性格 |
|---|---|---|
| **文献学・書誌の層** | 底本，初出，外字，踊り字，奥付 | 日本の近代文学研究の伝統的な語彙 |
| **コーパス言語学の層** | 母集団，標本，代表性，異なり語，未知語率 | 分野をまたいで共有される語彙 |
| **計算の層** | word embedding，Procrustes，LDA，交差検証 | 実装に直結する語彙 |

**この授業の難しさは三層を行き来するところにある。** 「外字が復元できて
いない」という書誌の層の問題が，「未知語率が高い」というコーパスの層の
数値に現れ，「トピックが汚れる」という計算の層の結果を生む。
用語を覚えるより，**層をまたぐ因果の鎖を言えるようにする**ほうが大事である。

# Step 0 環境構築 — 走る前の足場

> 参照: `docs/00_setup_students.md`，`scripts/00_env_check.py`

### キーワード

仮想環境 / `ALL OK` / 二層の置き場 / `/Users/Shared/jlit` / XCreds /
admin 権限 / UniDic / MALLET / JDK / `PYTHONUTF8` / Git で持ち運ぶ

---

#### 仮想環境 (virtual environment) ★

この授業のために必要な Python パッケージだけを入れた，隔離された作業場。
本授業では**作業フォルダ `~/Documents/dh_project/.venv`** に置く
（リポジトリ `JLit_Corpus_2026` はその中に clone する）。
`00_bootstrap_mac.sh` が作り，`source ~/Documents/dh_project/.venv/bin/activate` で入る。
リポジトリの中に置かないのは，`uv add` の行き先をカーネルと同じ環境に
揃えるためである（→「`uv add` はプロジェクト単位である」）。

**なぜ要るか**：共用機では前の受講生が入れたパッケージと衝突する。
また `sudo pip install` はマシン全体の Python を壊すので**禁止**である。
仮想環境に入っていれば `pip install` は自分の `dh_project/.venv/` だけを変える。

⚠ プロンプトの先頭に `(.venv)` が出ていなければ，**入っていない**。
「入れたはずのパッケージが無い」というつまずきの大半はこれである。

#### 二層の置き場 ★

重いもの（JDK・MALLET・UniDic 約 1.7 GB・取得済み XHTML）は
`/Users/Shared/jlit` に置き，軽いもの（自分のコード・図・レポート）は
自分のホームに置く。

**なぜ二層か**：`/Users/Shared` は macOS で **admin 権限なしに全ユーザが
読み書きできる**唯一の場所である。ここに置けば，同じマシンを使う次の受講生が
約 1.7 GB を取り直さずに済み，青空文庫への負荷も減る（1秒/件の取得を人数分
繰り返さない）。

#### XCreds / ホームはマシンごとに別々 ⚠

DH Lab の共用 iMac は XCreds 認証である。ゲストではなく各自のアカウントで
ログインするので，**ログインしたマシンに作られたホームはそのまま保持される**。
ただし**ホームはマシンごとに別々で，共有されない**。火曜に 2021-03 番ラベルの
マシンで作った `.venv` と成果物は，木曜に 2021-03 番なら残っているが，
2021-05 番には**無い**（2021-05 番には新しい
ホームが作られる）。故障ではない。

**対処**：`00_env_check.py` が毎回表示するマシン名をレポートに控え，
なるべく同じマシンを使う。成果物は毎回 `git push` して，どのマシンからでも
取り出せるようにしておく。

#### admin 権限を使わない方針

TA が admin 権限を持っているが，**マシン本体への変更は最小限に止める**。
Java も Temurin の tar.gz を展開する方式にしてあり，インストーラは使わない。
受講生が `sudo` を打つ場面は，この授業には一つも無い。

#### UniDic

国立国語研究所の形態素解析用辞書。**辞書であって，解析器ではない**
（解析器は MeCab / fugashi）。現代語・古文・方言など**変種ごとに別の
辞書**が配布されている（版は日付ベース。現在 v202512）。

本コーパスの**本番の辞書は近現代口語小説UniDic（`unidic-novel`
v202512）**である。2026-09-22 に 4 辞書を 111 点で比べて決めた
（→「辞書の選定」Step 3）。zip で約 1.7 GB あるので，共用機では
`/Users/Shared/jlit/unidic-novel-v202512` にユーザが**1回だけ**展開する。

⚠ `pip install unidic` → `python -m unidic download` で入るのは
**現代書き言葉（cwj）であって本番の辞書ではない**。→ Step 3

#### MALLET

トピックモデル（LDA）の実装。Java で動くので **JDK が要る**。
Windows では `C:\JLit\mallet\` のように**空白を含まないパス**に置く。
→ Step 8

#### `PYTHONUTF8=1`（Windows 固有）⚠

Windows の Python は既定の文字コードが UTF-8 ではないため，日本語の
ファイルを読むと文字化けするか例外になる。環境変数 `PYTHONUTF8=1` を
設定して回避する。macOS では不要。

#### `00_env_check.py` / `ALL OK`

Python の版・必要パッケージ・UniDic・MALLET・日本語フォントを
一括で点検するスクリプト。**`ALL OK` が出るまで Step 1 の先へ進まない。**
足りないものは，表示された指示のとおりに導入する。

#### `my_work/` / `setup_my_work.sh` / `copy_notebooks.py` / `update.sh` ⚠

置き場は3つに分かれる。**コースのリポジトリ**（教材。受講生は pull だけ），
**自分のバックアップ**（`my_work/`。自分の GitHub の private リポジトリへ push），
**Zulip**（課題の提出と読み合い）である。

`notebooks/` は**配布版**，`my_work/notebooks/` は**自分用のコピー**である。
Jupyter で開いて実行するのは必ず `my_work/notebooks/` の方。配布版を実行すると
出力が `.ipynb` に書き込まれて「手元で変更したファイル」になり，
次の `git pull` が止まる。`my_work/` はコースのリポジトリの `.gitignore` で除外してあり，
その中は**独立した git リポジトリ**である。図・表は `my_work/results/` に書き出される。

- `bash scripts/setup_my_work.sh <GitHubのユーザ名>` — 初回と，初めてのマシンで1回。
  コースへの push を無効にし，`my_work/` を git にして自分の `jlit-work` を push 先にし，
  バックアップがあれば取ってくる。50 MB を超えるファイルのコミットを止めるチェックも置く
- `python scripts/copy_notebooks.py` — まだ無いノートブックを `my_work/notebooks/` にコピーする。
  教員が直した版は，自分のコピーが未編集なら置き換え，編集済みなら
  `__新版_<月日>` を付けた別名で置く（自分の版は消さない）。課題のテンプレート
  （`templates/StepN_report.md`・`final_report.md`）も同じ規則で `my_work/results/` に置く
- `bash scripts/update.sh` — **素の `git pull` の代わりに，毎回の授業のはじめに使う。**
  手元で変わった配布ファイルと，新しく届くファイルと同名の手元ファイルを
  `my_work/_backup/<日時>/` に退避してから最新版に進め，`my_work/` をバックアップと揃え，
  最後に `copy_notebooks.py` を呼ぶ。`--dry-run` で予定だけ表示

→ `00_setup_students.md` §5・§6・§6.1

# Step 1 コーパスとは何か — 設計・代表性・診断

> ノートブック: `01_corpus_design.ipynb`
> 参照: `docs/representativeness_report.md`

### キーワード

母集団 / 標本 / 代表性 / 偏り / メタデータ / 典拠 / NDC / 初出年 /
文語・口語 / `style_class` / 順序尺度と名義尺度 / 重複 / 外字の喪失 /
奥付の混入 / SVG

---

#### 母集団 (population) と標本 (sample) ★

- **母集団** … 本当に知りたい対象の全体。ここでは「1868–1960年に日本語で
  書かれた文学テクストの全体」。
- **標本** … 実際に手元にあるもの。ここでは「青空文庫にあり，著作権が切れ，
  誰かが入力した作品」。

**この授業の出発点は，両者が一致しないという自覚である。**

#### 代表性 (representativeness) ★

標本が母集団をどれだけ歪みなく写しているか。Biber (1993) の古典的な論点。

**なぜ最初に置くか**：標本が歪んでいると，どれほど精緻なモデルを当てても
**その歪みを測ることになる**。「昭和期の小説は語彙が平易になった」という
結論が出ても，昭和期の7点が児童向け読物なら，測ったのは時代ではなく読者層である。

⚠ 代表性は**点数では買えない**。100点あっても全部が同じジャンル・同じ
作家なら代表性は低い。数える軸（時代・ジャンル・作家・読者層・文体）
ごとに別々に評価する。

#### 偏り (bias)

ある軸の分布が母集団と違うこと。本コーパスの v1（64点）では，
時代（昭和戦前に集中），ジャンル（探偵小説が厚い），作家
（森鴎外7点・岡本綺堂6点…），読者層（児童向けの塊）に偏りがあった。

⚠ **作品数の偏りと語数の偏りは別物である。** 短篇が多いジャンルは
作品数では厚く見えるが語数では薄い。必ず両方で数える。

#### メタデータ (metadata) と典拠 (source / authority) ★

メタデータは「本文についての情報」（作者・初出年・ジャンル・文体…）。
**典拠**は，その値が**どこから来たか**の記録。

> **データを作る人は，列の意味を1行で説明できなければならない。
> 説明できない列は，必ずあとで誤用される。**

v1 の `genre` 列は英語・日本語・別題・誤綴が混在し（"Histrical novel"，
「（二十世紀鉄仮面）」），`brow` 列は high/low の二値に児童書と
ノンフィクションが押し込まれていた。いずれも典拠を持たない列である。

#### 初出年 (year of first publication) ⚠

**作品が最初に世に出た年**。底本（いま手元で使っている本）の刊年ではない。

v1 は小栗虫太郎『潜航艇「鷹の城」』を **1977年** としていた。これは
戦後の全集の刊年で，初出は **1935年**。この誤りは通時分析を丸ごと壊す。
→ Step 2 で青空文庫の書誌索引から取り直す。

#### NDC（日本十進分類法）

図書館の分類番号。`913` は日本の小説・物語。v1 は番号ではなく
「小説、物語」というラベル文字列を入れていた。

#### 文語 / 口語 と `style_class`

- `bungo_per10k` … 文語助動詞標識（なり・けり・べし・ごとし…）の1万語あたり頻度
- `kogo_per10k` … 口語助動詞標識（です・ます・である…）の1万語あたり頻度
- `style_class` … `A_文語体` / `B_過渡` / `C_口語体` の3分類

この2軸の散布図が**言文一致運動の前後**を1枚で見せる図になる。

#### 順序尺度 (ordinal) と名義尺度 (nominal) ★

- **順序のあるもの** … 初出年・時代・段階。→ **1色相の濃淡**で色分けする
- **順序の無いもの** … ジャンル・作家。→ 色相で分ける

⚠ **時代をカテゴリ用の8色で色分けしてはいけない。** 明治中期が青で明治後期が
黄なら，隣り合う時代が隣り合う色にならず，「時代が下るにつれて点がどちらへ
動くか」という肝心のことが読めない。

本授業では初出年を **5段**（`year_bands()`）に畳んで青の濃淡に割り当てる。
6段にできないのは，1色相の濃淡で順序を見せるには隣り合う段の明度差が
0.06 以上必要なのに，白地で使える青の幅が明度差にして 0.30 ほどしか
ないからである。

#### v1 の3つの重大な欠陥 ★

Step 1 の演習で**自分の手で再発見する**ことになっている。

| 欠陥 | 実際 | 由来 |
|---|---|---|
| **重複** | 『灰色の巨人』の本文が『魔法博士』と同一。実効サンプルは 64 ではなく **63** | 取得ミス |
| **外字の喪失** | `※［＃「…」、第4水準2-81-40］` から `［＃…］` だけを削り `※` が残る。全 **592箇所** | 正規表現による削除 |
| **奥付の混入** | 『敗戦日記』末尾に「入力：青空文庫／校正：…」がそのまま残る | 本文抽出の失敗 |

**3つとも「要らないものを正規表現で削る」方針の副作用である。**
Step 2 からは**削らずにタグで分離する**方針に切り替える。

#### SVG (Scalable Vector Graphics)

図の保存形式。本授業では**すべての図を PNG ではなく SVG で出す**。
拡大しても劣化せず，あとから Illustrator 等で微修正でき，学術誌の
ベクタ形式要求に通るため。`save_fig()` が自動でそうする。

⚠ **画面に出る図と保存される図は別物**。ノートブック内の表示は PNG だが，
`results/` に保存されるファイルは SVG である。

---

### 確認問題

1. 「このコーパスは100点あるから代表性が高い」という主張の誤りを指摘してみよう。
2. v1 の3つの欠陥に共通する原因は何か。Step 2 はその原因にどう対処するか。
3. 時代を色で示すとき，カテゴリ用の8色を使ってはいけないのはなぜか。
4. 初出年と底本刊年を取り違えると，どの分析が壊れるか。

<details>
<summary><b>解答</b>（自分の答えを書いてから開く）</summary>

1. 代表性は点数ではなく**分布**の問題。100点が全部同じジャンル・同じ作家
   なら代表性は低い。軸ごとに，作品数と語数の両方で評価する必要がある。
2. **要らないものを正規表現で削った**こと。削除は不可逆なので，消えたことに
   誰も気づけない。Step 2 では削らず，`<g>` `<note>` `<said>` などの
   **タグで分離**し，何を数えるかは後段の設定で決める。
3. 順序のあるものを名義尺度として扱うことになり，隣り合う時代が隣り合う色に
   ならない。「時代が下るとどちらへ動くか」という勾配が読めなくなる。
4. 通時分析のすべて。時代スライス（Step 6）・トピックの通時変化（Step 8）・
   doc2vec の時代効果（Step 7）が，存在しない時代配置の上で計算される。

</details>

# Step 2 再構築(1) — 書誌の典拠と XML マークアップ

> ノートブック: `02_rebuild_xml.ipynb`
> 参照: `docs/encoding_guidelines.md`，`scripts/03_aozora2xml.py`

### キーワード

TEI / 分離と削除 / 書誌索引 / マニフェスト / 未解決行 / 外字 / 面区点 /
`euc_jis_2004` / ルビ / `<said>` / `<quote type="embedded">` / `@part` /
`speech_markup` / 分冊結合 / `<div type="volume">`

---

#### TEI (Text Encoding Initiative) ★

人文学テクストの構造をタグで記述するための国際的な指針。
本授業では完全準拠ではなく「TEI 風」の語彙を使う。

**中心思想**：
> **本文とメタ情報を「分離」し，何を数えるかは後段の設定で決める。**

削除（v1 の方針）は不可逆だが，分離なら後から取捨できる。ルビを数えたい
研究者も数えたくない研究者も，同じ XML から出発できる。

#### 青空文庫の2つの配布形式 ⚠

| | プレーンテクスト版 (.txt) | XHTML 版 (.html) |
|---|---|---|
| 文字コード | Shift_JIS | UTF-8 |
| ルビ | `渋江《しぶえ》` | `<ruby><rb>渋江</rb><rt>しぶえ</rt></ruby>` |
| 注記 | `［＃…］` | `<span class="notes">［＃…］</span>` |
| 外字 | `※［＃…］` | `<img class="gaiji" alt="※(噓, 1-84-7)">` |
| 奥付 | 本文と同じ平文 | `<div class="bibliographical_information">` |

**XHTML を使う。** 境界が要素で決まるので，正規表現の当て推量が要らない。

#### 書誌索引 (`list_person_all_extended_utf8.zip`) ★

青空文庫が公開する，全作品（約2万点）の作品ID・作品名・**初出**・
**NDC**・文字遣い種別・底本・親本・URL を収めた CSV。

**v1 の `year` 列の誤りは，この索引を使っていれば起きなかった種類の誤りである。**
図書カードを1件ずつ読む必要もない。一次資料に当たるとはこういうことである。

#### マニフェスト (`config/corpus_manifest.tsv`)

取りたい作品を**作者名＋作品名**で書いた一覧。スクリプトが索引と突き合わせて
ID・URL・書誌を解決する。**この突き合わせ作業そのものがコーパス構築の実務である。**

#### 未解決行の3分類 ⚠

| 原因 | 意味 | 対処 |
|---|---|---|
| `title_mismatch` | 著者は登録あり，作品名が一致しない | 候補を見てマニフェストの `title` を直す |
| `author_differs` | 同名作品が別の著者名の下にある | **翻訳作品**は原著者の下に入る（『即興詩人』→アンデルセン）。`author_ja` を直し，訳者は `note` へ |
| `author_not_found` | 著者そのものが青空文庫にない | **著作権保護期間中（没後70年）**。作品名を直しても解決しない |

`title_mismatch` の典型は表記ゆれ（『不如帰』vs『小説 不如帰』），
副題つき（『半七捕物帳 69 白蝶怪』），分冊（『夜明け前 01 第一部上』），
新字版・旧字版の併存（啄木『鳥影』）。

#### 外字 (gaiji) ★

底本にあるが，使っている文字コードで直接表せない文字。青空文庫は注記で
その正体を示す。

#### 面区点 (men-ku-ten) と `euc_jis_2004`

JIS X 0213 の文字位置を表す3つ組。`第4水準2-81-40` なら面2・区81・点40。

```
面1 → バイト列 0xA0+区, 0xA0+点
面2 → バイト列 0x8F, 0xA0+区, 0xA0+点
```

Python の `euc_jis_2004` コーデックで復号すれば文字が得られる
（`scripts/lib/aozora.py` の `menkuten_to_char()`）。

#### 外字注記の3形式 ⚠

面区点を与えてくれるのは**いちばん親切な形式にすぎない**。

| 形式 | 例 | 解決法 |
|---|---|---|
| 面区点 | `※［＃「广＋(炎/鳥)」、第4水準2-81-40］` | `euc_jis_2004` で復号 |
| Unicode | `※［＃「女＋（而／大）」、U+5A86、7巻-16-下-14］` | `chr(0x5A86)` |
| **字の名前だけ** | `※［＃小書き片仮名ヲ、160-9］` | 対応表を引く。無ければ欠字 |

3つめが曲者である。末尾の `160-9` は**底本のページ-行**であって面区点ではない。
これを面区点と読み違えると `※` が本文に残り，`※` は UniDic では記号1字として
数えられるので，**文字が失われたことが誰にも気づかれない**。

さらに `※` が**ルビの基底文字の中**に入ることがある。注記の直前が `</ruby>`
なので「直前の文字が `※` か」だけを見ていると取り逃がす。
森鴎外『伊沢蘭軒』だけで74箇所がこの形である。

#### `gaiji_resolved` / `gaiji_unresolved` / 残存 `※` ⚠

**三者はまったく違うものである。**

- `gaiji_resolved` … 実体を復元して `<g ref="…">侔</g>` に入れた
- `gaiji_unresolved` … 実体が不明なので `<g ref="unresolved" n="注記">` で残した。
  正規化後は `〓` になる
- 正規化後に残る **`※`** … 第3のもの。**欠陥とは限らない**。底本の編者が
  付けた注の印や伏字であることがある（海野十三『敗戦日記』の
  `（※マリアナ基地からの…）` 100箇所あまりは本文の一部である）

#### `<said>` — 会話と地の文の分離 ★

会話を囲むタグ。**語りの人称を測るときに必須**になる。地の文と会話を
一緒くたにすると，「一人称小説」の判定が会話中の「私」で狂う。

#### `@part="I|M|F"`

段落をまたぐ会話の断片を示す属性（Initial / Medial / Final）。
XML の入れ子は段落構造と交差できないので，段落末で閉じ，次の段落で開き直す。

#### `<quote type="embedded">` — 埋め込みテクスト

8段落以上にわたる引用，すなわち**書簡・演説・手記**。
『こころ』下「先生と遺書」（本文の51%），森鴎外『即興詩人』（30%），
夢野久作『ドグラ・マグラ』（6%）などが該当する。

枠物語の**内と外で文体を対照する**ために切り出してある。作家も時代も
同じなのだから，差が出ればそれは**枠構造そのものの効果**である。→ Step 3 の演習

#### `speech_markup` = `full` / `partial` / `none` ★⚠

その作品の会話標示が信用できるかの判定。`teiHeader` の
`<catRef scheme="speech_markup">` に記録される。

> **比率が 0 であることと，比率が測れないことは違う。**

- 樋口一葉『たけくらべ』『にごりえ』… 会話に括弧を用いず地の文に溶け込ませる
- 岡本綺堂『修禅寺物語』… 戯曲。会話は話者名と字下げで示される
- 福沢諭吉『福翁自伝』… 口述筆記。`「` で起こして「と云う」で閉じ `」` を置かない
  （本文中 `「` 330 に対し `」` 38）

これらを「会話文比率 0」として分析に入れると，文体指標も話法の通時変化も
系統的に歪む。**`full` 以外は欠測として扱う。`fillna(0)` をしない。**

#### `speech_mark` ⚠

その作品の**第一階層の会話符**。`「」` とは限らない。島崎藤村『破戒』は
`「」` が47に対し `『』` が1,574で，会話のほぼ全部が `『』` である。
一律に `「」` を会話と見ると，この作品の会話が**丸ごと0件**になる。

#### 分冊結合 (`03b_merge_volumes.py`) ★

青空文庫は長篇を分冊ごとに別カードで公開する（『夜明け前』4カード，
『家』上下2カード）。そのままでは**分析の単位が「作品」ではなく「冊」になる**。

| 何が起きるか |
|---|
| Delta や doc2vec の最近傍が，同じ作品の別の巻になる。「最近傍が同じ作家である割合」が自明に上がり，指標として意味をなさない |
| 1作家あたりの作品数が水増しされる（島崎藤村が9点に見えていたのは分冊のせい） |
| 語数・TTR・文体指標が巻ごとにばらけ，他の作品と比べられない |

TEI 的にも，分冊は1つの `<text>` の中の `<div type="volume">` であって
別の文書ではない。**XML の段階でまとめる。** もとの巻別 XML は
`data/xml/_volumes/` に退避されるので，巻ごとの比較をしたくなれば戻せる。

#### `completeness` の値

メタデータ上で，その行を分析に使うかどうかを決める列。

| 値 | 意味 | 集計に入るか |
|---|---|---|
| `complete` / `incomplete` / `part` / `partial` / `revised` | 本文がある | 入る |
| `merged` | 分冊結合で canonical に吸収された | **外れる** |
| `superseded` | より良い版に置き換えた | **外れる** |
| `too_short` | 短すぎて分析に耐えない | **外れる** |
| `DUPLICATE` | 本文が他と同一 | **外れる** |

#### 踊り字 (odoriji / iteration mark) ★

同じ字の繰り返しを表す記号。`ゝ ゞ ヽ ヾ`（仮名）と `〳〵 ／＼`（くの字点），
`々`（同の字点）がある。

**なぜ問題か**：正規化しないと UniDic が `たゞ` を未知語として切り出す。
すると副詞の `ただ` が消え，`た` `ゞ` という無意味な列ができる。

そして，その頻度は**作家の文体差ではなく底本の正書法の差**である。

| ファイル | ゝ | ゞ | ヽ | ヾ |
|---|---:|---:|---:|---:|
| 藤村『破戒』 | **218** | 0 | 0 | 0 |
| 岡本かの子『生々流転』 | 8 | **183** | 0 | 0 |
| 石川啄木『鳥影』 | 2 | 5 | **66** | 2 |
| 藤村『夜明け前』『家』『新生』『千曲川』 | **0** | 0 | 0 | 0 |

同じ藤村でも『破戒』（新字旧仮名）だけ 218 箇所。正規化しなければ
「藤村の文体は他と違う」という結論が，実は底本の違いを測ることになる。

#### 展開規則

| 記号 | 規則 | 例 |
|---|---|---|
| `ゝ` | 直前の平仮名を反復（直前が濁音なら清音化） | `はゝ` → `はは` |
| `ゞ` | 直前の平仮名を濁音化して反復 | `たゞ` → `ただ` |
| `ヽ` `ヾ` | 片仮名版 | `ドヾ` → `ドド` |
| `／＼` `〳〵` | 直前の仮名連続（2–4字）を反復 | `いろ／＼` → `いろいろ` |
| `／″＼` `〴〵` | 同上・濁音化 | `しみ〴〵` → `しみじみ` |
| `々` | **展開しない** | `人々` → `人々` |

#### `々` を展開してはいけない理由 ⚠★

`々` は UniDic に**語彙素として登録されている**（人々・時々・我々）。
`人人` に展開すると，かえって未知語になる。

> **踊り字だからといって一律に扱わない。辞書の挙動を確かめてから決める。**

この一事が本授業の方法論そのものである。規則は，それを適用する先の道具
（ここでは UniDic）の性質を確かめてから決める。

#### くの字点と `@resp="auto"`

くの字点は「直前の何字を繰り返すか」が原理的に曖昧である（2–4字を推定する）。
機械推定であることを `@resp="auto"` として**記録に残す**。
あとから人手で直せるようにするためである。

#### 4つのストリーム ★

`04_normalise.py` は XML から4種類の平文を作る。

| ストリーム | 内容 | 使いどころ |
|---|---|---|
| `full` | 地の文＋会話 | **既定の分析対象** |
| `narration` | 地の文のみ | 語りの人称を測るとき |
| `speech` | 会話のみ | 会話文比率・役割語の分析 |
| `embedded` | 書簡・手記など埋め込みテクスト | 枠構造をもつ作品の内部対照 |

いずれも `<note>` は除外，ルビの読みは除外，`<g>` は復元文字に置換される。

#### 形態素解析 (morphological analysis)

日本語には語の切れ目が無いので，まず**語に切る**。同時に品詞・活用形・
語彙素などの情報が付く。解析器は **MeCab**（Python からは **fugashi**），
辞書は **UniDic**。

⚠ **解析器と辞書は別物。** 「UniDic で解析する」は正しくは
「MeCab を UniDic で走らせる」である。辞書を替えれば結果は変わる。

#### 辞書の選定 (dictionary selection) ★⚠

**どの辞書で解析するかは，研究設計の決定である。** 前処理の設定では
ない。辞書を替えれば語数・未知語率・語彙素の体系が変わるので，
**別の辞書で数えた表を並べて比べると，作品の違いではなく辞書の違いを
見ていることになる**。しかもエラーは出ない。

本コーパスの決定（2026-09-22。4 辞書・111 点）:

| 辞書 | 未知語率 | 平均語長 | 役 |
|---|---:|---:|---|
| **`unidic-novel`**（近現代口語小説） | **0.17%** | 1.575 | **本番** |
| `unidic-qkana`（旧仮名口語） | 0.19% | 1.577 | 次点（実質同等） |
| `unidic-kindai-bungo`（近代文語） | 0.25% | 1.582 | **検算用** |
| `unidic-cwj`（現代書き言葉） | 0.66% | 1.560 | 使わない |

**読み方の要点。** 未知語率が下がっただけでは良い辞書とは言えない。
語を**細かく刻めば**未知語率は下がるからである。だから平均語長を
同時に見る。novel は cwj より**未知語が少なく，かつ語が長い**。
したがって「細かく分割して稼いだ」のではないと言える。

⚠ 判断の規則（どの指標を優先するか，引き分けならどうするか）は
**測る前に決めておく**。測ってから決めると，出た数字に都合の良い
規則を選ぶことになる。→ `docs/dictionary_comparison.md` §4・§10

道具: `12_dict_compare.py`（内在指標）／`13_pipeline_compare.py`
（外在指標）／`check_unidic_dir.py`（展開の検査）

#### UniDic の4つの語形 ★⚠

**これは結果を左右する決定である。**

| 素性 | 「噓を」 | 「渋江」 | 「云つた」 |
|---|---|---|---|
| surface（表層形） | 噓 | 渋江 | 云つ |
| orthBase（書字形基本形） | 噓 | 渋江 | 云う |
| **lemma（語彙素）** | 嘘 | **シブエ** | 言う |
| lForm（語彙素読み） | ウソ | シブエ | イウ |

`lemma` は異表記（噓／嘘，云う／言う）を統合するので**通時比較に向く**。
ただし**固有名詞では片仮名の読みになる**という UniDic の仕様がある。
人名・地名が全部カタカナになると，特徴語リストが読めなくなる。

#### `--lemma-policy mixed`（本授業の既定）

```
固有名詞  → orthBase（なければ表層形）
それ以外  → lemma（なければ orthBase → 表層形）
```

`lemma` の通時的な強みを取りつつ，固有名詞のカタカナ化を避ける折衷。
加えて `私-代名詞` のような**同形異義接尾辞**は既定で落とす。

#### 未知語率 (OOV rate) ★

辞書に無い語の割合。**前処理の良し悪しを測る最良の単一指標**である。

読み方 —— 未知語の上位に何が来るかで対処が変わる。

| 上位に来るもの | 意味 | 対処 |
|---|---|---|
| 人名・地名 | 正常（固有名詞は辞書に限界がある） | 何もしない |
| カタカナ外来語 | 正常（**開いた類**なので必ず残る） | 何もしない |
| `ゝ` `ゞ` を含む列 | **正規化漏れ** | `04` の設定を見直す |
| `※` `〓` | **外字が復元できていない** | `03` の変換を見直す |
| 文語の活用形（`けれ` `ざり` `べかり`） | **辞書の被覆の問題** | 辞書の選定で解く（→「辞書の選定」） |

⚠ 未知語率は**正書法と強く相関する**。cwj で測った値では，新字新仮名の
中央値が 0.22% に対し新字旧仮名 0.61%，旧字旧仮名 1.81%。作品間で
単純に比べず，**正書法で層別してから**比べること。

#### ⚠ 未知語率は「何を測る指標か」が変わる ★

前処理を直し，辞書を口語小説向けに替えると，**残る未知語の大半が
カタカナ外来語と固有名詞になる**（本コーパスで実測: 0.66% → 0.17%）。

このとき未知語率は，もはや「正書法の乱れ」を測っていない。
**外来語と固有名詞の密度**を測っている。同じ名前の指標が，同じ計算式で，
別のものを測るようになる。だから

- 前処理の品質指標として使うなら，**未知語の中身を見てからにする**
  （`14_unknown_profile.py` が 8 分類に分けて出す）
- 辞書を替える前と後の未知語率を**並べて比べてはいけない**

⚠ 未知語リストは**片側しか映さない**。辞書に無い語は未知語として現れるが，
**辞書にある語に無理に分割された箇所は現れない**（`ストツキング` →
`ストツ`＋`キング` は「既知語2語」になる）。未知語率が下がっても，
分割の誤りが増えている可能性は残る。`14_unknown_profile.py` の
`scan_forced_splits` はこの側を探す道具である。

#### チャンク (chunk) ★

作品を一定語数（既定 **2,000語**）に切り分けた分析単位。

**なぜ要るか**：作品長の開きが大きすぎる。v1 では 30,555語（鴎外
『大塩平八郎』）から 502,937語（藤村『夜明け前』）まで **16.5倍**。
作品を1文書としてトピックモデルにかけると，長篇1作が数トピックを独占する。

#### `--max-chunks` と `--min-chunk`

- `--max-chunks 40` … 1作品あたりのチャンク数の上限。超えたぶんは抜き出す
- `--min-chunk` … これに満たない端数チャンクは捨てる。**既定は `--chunk` の半分**

⚠ `--chunk` を上げると `--min-chunk` も上がり，**短い作品がコーパスから
丸ごと落ちる**。`works_too_short.csv` で何点落ちたか必ず確認すること。

#### `--sample` — 抜き出し方4種 ★

| 値 | 何をするか | いつ使うか |
|---|---|---|
| `stratified` | 作品を40等分し，各区画から1つ無作為に抜く（**既定**） | 標準。冒頭・中盤・結末が必ず入る |
| `random` | 作品全体から無作為に抜く | 層化の必要がないとき |
| `spread` | 等間隔に抜く | 乱数を使いたくないとき |
| `head` | 先頭から | **使わない**。冒頭に偏る |

既定を `stratified` にしたのは**被覆**のため。単純無作為で107から40を引くと，
たまたま連続した区間が抜け落ちる（最大8チャンク＝約16,000語）。物語の位置と
主題が相関する長篇では，その区間の話題が標本から丸ごと落ちる。層化すれば
区間の抜けは最大5チャンクに収まる。

⚠ **層化しても無作為性は失われない。** 区画の中でどれを引くかは乱数が
決めており，`spread`（等間隔＝決定論的）とは別物である。

#### 乱数シード (random seed) と再現性 ★

シードは `f'{seed}:{作品の語幹}'` として**作品ごとに**作る。

**なぜ作品ごとか**：`random.seed()` を最初に一度だけ呼ぶ実装だと，各作品の
標本は「それまでに何回 random を呼んだか」に依存する。**作品を1点足しただけで，
後ろに並ぶ全作品の標本が入れ替わり，前回の結果と比べられなくなる。**

論文には最低でも `--chunk` `--max-chunks` `--seed` の3つを書く
（本授業の既定は `--chunk 2000` `--max-chunks 40` `--seed 20260920`，
`--sample stratified`。`config/pipeline.yaml` に記録してある）。

z 標準化 / Burrows's Delta / 最近傍 / PCA / 対数尤度比 G² / 効果量 /

**重なり率** / 作家効果と時代効果の交絡

#### 文体計量 (stylometry) ★

文体を数量的に記述する方法。中心的な発見は逆説的である。

> **作者を最もよく識別するのは，内容と無関係な機能語の頻度である。**

「の」「は」「て」「が」の使用比率は作家ごとに驚くほど安定し，主題が
変わっても変わらない。だから作者推定に使える。

⚠ **逆に言えば，時代やジャンルを見たいときは，機能語が作家効果を持ち込む。**
本コーパスは同じ作家の作品を複数含む（森鴎外7点，岡本綺堂6点，
坂口安吾・海野十三・島崎藤村が各5点…）ので，この交絡は強く出る。

#### MFW (Most Frequent Words) ★

最頻語。コーパス全体で頻度上位 N 語（100 / 300 / 1000 など）を取り，
その相対頻度を文書のベクトルとする。N の選び方は結果に効くので必ず報告する。

#### TTR (Type-Token Ratio) ⚠★

異なり語数（type）÷ 延べ語数（token）。直感的だが**標本サイズに強く依存する**。
長い作品ほど必ず下がる。

| 作品 | 語数 | TTR×1000 |
|---|---:|---:|
| 海野十三『敗戦日記』 | 50,131 | 169.5 |
| 藤村『夜明け前』 | 502,937 | **45.2** |

**『夜明け前』の語彙が貧しいのではない。長いだけである。**
長さの違う作品を比べるときは TTR を使わない。

#### 長さに頑健な語彙指標

| 指標 | 定義 | 性質 |
|---|---|---|
| **Guiraud's R** | V / √N | TTR の長さ依存を平方根で緩和 |
| **Yule's K** | 頻度分布の集中度 | 長さにほぼ依存しない |
| **エントロピー** | 頻度分布の不確実性（bit） | 分布の偏りを測る |

#### z 標準化 (z-score standardisation) ★

各語について（値 − 平均）÷ 標準偏差。

**なぜ要るか**：Delta では**頻度の大小によらず各語を等しく扱いたい**。
標準化しないと「の」の差だけが距離を支配し，他の499語が効かなくなる。

#### Burrows's Delta ★

作者推定の標準手法。3段階で実装できる。

1. 最頻語 N 語の**相対頻度**行列を作る
2. 語ごとに **z 標準化**する
3. 文書ペアの z 値の**絶対差の平均**を距離とする

単純さが強みで，少ない訓練データでもよく効く（Burrows 2002; Evert et al. 2017）。

**標準偏差は母標準偏差**（Excel の `STDEVP`，numpy の `ddof=0`）で揃えてある。
pandas の `.std()` は既定が `ddof=1`（標本標準偏差）なので，**そのまま使うと
Excel や `07_descriptive_stats.py` と値がずれる。** `std(ddof=0)` と書くこと。

#### 作者推定としての Delta — 既知の作品と問題のテクスト

Burrows (2002) の元の使い方は「作者の分かっている作品群（既知）」と
「作者を伏せたテクスト（問題）」を比べることである。

- **最頻語・平均・標準偏差は既知の作品だけから決める。** 問題のテクストが
  物差しを動かさないため
- 候補は**作品ごと**にも，**作家プロファイル**（その作家の作品の z の平均）
  ごとにも比べられる。作品ごとだと，語りの人称や登場人物名が近い
  **別の作家の作品**が割り込むことがある
- Delta は「候補の中で誰に近いか」しか答えない。真の作者が候補に
  いなくても，いちばん近い誰かは必ず出る

Step 4 §2 では，これを Excel で1手順ずつ計算する
（`scripts/17_delta_workbook.py` → `my_work/results/Step4_delta_manual.xlsx`。
最頻語 50 語・既知 4 作家 × 2 作品・作品X 1 点）。

#### 最近傍 (nearest neighbour) と一致率

ある作品から見て距離が最小の作品。その最近傍が**同じ作家**である割合と，
**同じ時代**である割合を比べることで，距離空間が何を捉えているかが分かる。

⚠ **分冊を結合していないとこの指標は意味をなさない**（最近傍が同じ作品の別の巻になる）。
→ Step 2

#### PCA (主成分分析) ★

多次元の行列を，分散の大きい方向から順に少数の軸に要約する。
MFW の z 行列に当てると，第1・第2主成分に何が現れるか——
**時代か，ジャンルか，作家か，文語/口語か**——を見る。

⚠ **射影は必ず情報を失う。** 2次元の図は探索の道具であって，証拠ではない。

#### 対数尤度比 G² (log-likelihood ratio) ★

2つのコーパスで語の頻度を比べる標準的な方法。

$$G^2 = 2\left(a\ln\frac{a}{E_1} + b\ln\frac{b}{E_2}\right)$$

ここで，ある語について，比べる2つのコーパス（Step 4 では「その時代」と
「それ以外の時代」）での頻度を $a, b$，各コーパスの総語数を $c, d$ とする。

| | コーパス1 | コーパス2 | 計 |
|---|---:|---:|---:|
| その語の頻度 | $a$ | $b$ | $a+b$ |
| 総語数 | $c$ | $d$ | $c+d$ |

$E_1 = c\,(a+b)/(c+d)$，$E_2 = d\,(a+b)/(c+d)$ は**期待値**，すなわち
「2つのコーパスでその語の使われ方に差が無い」という帰無仮説のもとで
期待される頻度である。

G² の値は，実際の頻度 $a, b$ と期待値とのずれが**偶然では起こりにくい
度合い**を数値化したものである。値が大きいほど，そのずれは偶然では
説明しにくい。ただし，G² が大きいことは，実際の頻度と期待値の**比**が
大きいこと（差が大きいこと）を意味しない。比が同じでも，頻度の高い語
ほど G² は大きくなる。差の大きさは効果量（log ratio）で別に見る
（下の注意点 1）。

**注意点が3つある。**

1. G² は**標本サイズに比例して大きくなる**。大きいコーパスでは些細な差も
   有意になる。必ず**効果量**（log ratio）を併記する。
2. 1作家に偏った時代では，**その作家の固有名詞**が上位に来る。
   「時代の特徴語」ではなく「特定作家の語彙」を見ていないか確認する。
3. **G² は「どこで多いか」を見ない。** 総頻度と総語数だけから計算するので，
   1作品に固まる語と全作品に薄く広がる語を区別できない。→ 散らばり

#### 効果量 (effect size)

差の**大きさ**。統計的有意性（差が偶然でないか）とは別の概念。
G² は有意性の指標なので，log ratio のような効果量と併記しないと
「巨大なコーパスではすべてが有意」という無意味な結論になる。

#### 散らばり（ディスパーション） (dispersion) — bursty か evenly-distributed か ★⚠

**頻度が同じでも，出かたが違えば意味が違う。** 次の2語は，どちらも
明治後期に 160 回・他の時代に 0 回とすると，**G² も log ratio も完全に
同じ値になる**（人工データで G²=221.01）。

| 語 | 出かた | 呼び名 |
|---|---|---|
| A | 明治後期の8作品すべてに 20 回ずつ | **evenly distributed**＝時代の書き方 |
| B | 明治後期の**1作品だけ**に 160 回 | **bursty**＝その作品の語彙 |

区別するには散らばりを測る。`keyness_by_period.csv` の列:

| 列 | 何を測るか | bursty なら |
|---|---|---|
| `df_all_prop` | 全作品のうち何割に出るか（文書頻度） | 小さい |
| `df_in_prop` | その時代の作品のうち何割に出るか | 小さい |
| `dp_in` | **その時代の中での** DP | 1 に近い |
| `top_work_share` / `top_work` | 最多の1作品が総頻度の何割を占めるか／それはどれか | 1 に近い |

#### DP (deviation of proportions, Gries 2008) ★

散らばりの指標。各部分コーパスについて「その語の何割がそこにあるか」と
「そこがコーパスの何割か」の差を取り，総和の半分にする。
**0＝完全に均等，1＝一点に集中。** 部分の大きさ（作品長）を織り込むので，
長篇に偏った語を正しく罰する。文書頻度（df）は出たか出ないかの 0/1 しか
見ないので，「広く薄く出るが1作に集中する」語を見落とす。**併せて読む。**

⚠ **時代別の特徴語では，コーパス全体の DP を使わない。**
ある時代だけに出る語は，その時代の全作品に均等に出ていても全体では
「偏った」語になり，DP が 0.5 前後になる。しかしその偏りは時代の
特徴語として**望ましい**偏りである。分母をその時代に限った `dp_in`
を使う（上の A は 0.004，B は 0.871。全体の DP はどちらも約 0.50）。

#### culling ★

**一定割合の文書に現れない語を特徴量から外す**操作。
*culling at 10%* なら，コーパス全体の文書頻度が 10% 未満の語を捨てる。
本コーパスで分析に使うのは 108 点なので 11 点未満に出る語が落ちる。

由来は Hoover (2004a, b)。Delta の検証で，**1つの作品が出現の大部分を
占める語**と人称代名詞を外すと精度が大きく上がることを示した。
文書頻度の閾値として定式化したのは R の stylo パッケージ
（Eder, Rybicki & Kestemont 2016）で，本授業の culling はこちらである。
Hoover の元の規則は文書頻度ではなく偏りそのものを見ている
（Step 4 の表の「最多作品の占有」がその量にあたる）。

⚠ **culling は G² の値を変えない。** 語を1つ落としても他の語の
`a, b, c, d` は変わらない（`c, d` は総語数で，特徴量の集合とは無関係）。
変わるのは**リストの中身と順位**だけである。「culling したら G² が動いた」
なら，語ではなく**トークンを消している**（総語数が変わっている）。
その2つは別の操作である。

⚠ **閾値は bursty さの代理にすぎない。** df の規則は2種類の取りこぼしを
する — 「多くの作品に1回ずつ出るうえで1作品に大量に出る語」（弾かれない
のに bursty）と，「作品数の少ない時代のために df が届かない語」（弾かれる
のに均等）。`Step4_keyness_dispersion.svg` の左上と右下がそれである。

⚠ **閾値は測る前に決める。** 3通り試して「いちばんきれいな」閾値を選ぶのは，
結果に合わせて規則を選ぶことである。複数試すのは**感度分析**として行い，
本分析の閾値は先に宣言して報告に書く。

#### Zeta / Iota

Burrows (2007) が Delta に続けて提案した，**最頻語より下の頻度帯**を使う指標。
Zeta は中頻度の語，Iota は低頻度の語を使う。Delta（最頻語）と合わせて，
頻度のどの層にも作者の手がかりがあることを示した。

Zeta はテクストをチャンクに区切り，語が**出るか出ないかだけ**を数える。
Craig & Kinney (2009) の形では
Zeta =（群 A でその語を含むチャンクの割合）−（群 B でその語を含むチャンクの割合）
で，−1 から +1 の値を取る。頻度を数えないので，1作品に大量に出る語
（bursty な語）に引きずられない。**culling が語を外して bursty さに対処する
のに対し，Zeta は数え方を変えて対処する。** 変種の比較は Schöch ほか (2018)。
本授業では計算しないが，研究史として Step 4 の 4.4 で扱う。

#### representativeness / distinctiveness（特徴語の条件）

Klaussner, Nerbonne & Çöltekin (2015) が特徴語の条件として分けた2つ。
**representativeness** はその作者の作品のどれでも同じように使われること，
**distinctiveness** は他の作者と使い方が違うこと。G² は後者しか見ない。
方言学の方法（Prokić, Çöltekin & Nerbonne 2012）に由来する。
⚠ Step 1 の「コーパスの代表性 (representativeness)」とは別の概念である。

#### Random Forests による特徴語の抽出

Tabata (2012, 2015) は，Random Forests（Breiman の決定木のアンサンブル）を
応用して Dickens を Collins・参照コーパスと判別する特徴語セットを特定した。
語の順位付けには variable importance（mean decrease accuracy・
mean decrease Gini）を用いた。対数尤度比の
特徴語が固有名詞と分布の偏りに引きずられるのに対し，作品を単位に学習する
分類器は1作品にしか出ない語を重視しない。Step 4 の 4.4 で扱う。

#### 重なり率 (overlap) — リストがどれだけ変わったか

culling の有無で特徴語リストがどれだけ変わったかを数える指標。

| 指標 | 定義 |
|---|---|
| 残存率 | culling 後に残る有意語の割合 |
| 重なり@k | そのままの上位 k 語のうち culling 後も上位 k 語に残る割合 |
| 入替@k | culling 後の上位 k 語のうち，元は上位 k 語に無かった語数 |

⚠ 分母は `k` ではなく **`min(k, 実際の有意語数)`**。有意語が k に満たない
時代で k で割ると，重なりが不当に低く出て「culling で激変した」と読める。

⚠ **Spearman の ρ を「そのまま vs culling 後」で計算しても意味がない。**
culling は語を落とすだけで残った語の順序を変えないので，**ρ は必ず 1**
になる。使うなら「G² の順位」と「`dp_in`」の相関を見て，*このコーパスでは
上位の特徴語ほど bursty なのか*を問う。

---

### 確認問題

1. なぜ機能語が作者推定に効くのか。そしてなぜそれが通時研究の障害になるのか。
2. 『夜明け前』の TTR が低い。「藤村の語彙は貧しい」と言えるか。
3. Delta で z 標準化を省くと何が起きるか。
4. G² の上位に固有名詞が並んだ。何を疑うべきか。
5. 2つの語が同じ G²・同じ log ratio を得た。一方は8作品に 20 回ずつ，
   他方は1作品に 160 回である。**どちらを「時代の特徴語」と呼べるか。
   そしてそれを G² の表から見分けられるか。**
6. culling at 10% を適用したら G² の値が変わった。何を間違えたか。
7. 「そのまま」と「culling 後」の上位50語で Spearman の ρ を取ったら
   1.00 になった。なぜか。代わりに何を測るべきか。

<details>
<summary><b>解答</b>（自分の答えを書いてから開く）</summary>

1. 機能語の使用比率は主題に左右されず作家ごとに安定しているため。
   逆に言えば，同じ作家の作品が複数あるコーパスでは，時代やジャンルの
   効果を見ようとしても**作家効果が持ち込まれる**（交絡）。
2. 言えない。TTR は標本サイズに強く依存し，長い作品ほど必ず下がる。
   Guiraud's R や Yule's K のような長さに頑健な指標で比べる。
3. 高頻度語（「の」など）の差だけが距離を支配し，残りの語が効かなくなる。
   Delta の狙い（各語を等しく扱う）が失われる。
4. その「時代の特徴語」が，実は，**特定作家・特定作品にかたまって生起する
   （bursty な）語彙**である可能性。
   `data/tokens/tsv/` の品詞情報で固有名詞を除いて再計算し，比較する。
5. 前者（evenly distributed）だけが時代の書き方と呼べる。後者は bursty で，
   その1作品の語彙である。**G² の表からは見分けられない。**
   G² は総頻度と総語数しか見ないので，両者の値は一致する。
   `df_all_prop` / `dp_in` / `top_work_share` のような散らばりの列が要る。
6. 語を落とす（特徴量の culling）のではなく，**トークンを消している**。
   総語数 `c, d` が変われば G² も動く。culling は特徴量の集合を絞る操作で，
   コーパスの語数には触れない。
7. culling は語を落とすだけで残った語の順序を変えないので，
   生き残った語の順位は必ず単調に対応し ρ=1 になる。測るべきは
   「上位 k 語の重なり」と「入れ替わった語」，および
   「G² の順位と `dp_in` の相関」である。

</details>

# Step 5 word2vec の原理

> ノートブック: `05_word2vec_basics.ipynb`

### キーワード

分布仮説 / 共起行列 / PPMI / SVD / word embedding(s) / CBOW / skip-gram /
window / dim / min_count / 近傍語 / 類推 / t-SNE / **UMAP** /
**語彙のギャラクシー** / **信頼度（trustworthiness）** / **近傍保存** /
**語の列（表層形・語彙素・内容語）** / 安定性 / Jaccard

---

#### 分布仮説 (distributional hypothesis) ★

> "You shall know a word by the company it keeps." — J. R. Firth (1957)

語の意味は，その語が現れる**文脈の分布**で近似できる，という仮説。
word2vec はこれを「文脈語を予測する浅いニューラルネットの重み」として
実装したものにすぎない。

#### word embedding(s)（word vector(s)）★

語を低次元（本授業では 300 次元）の実数ベクトルで表したもの。
**学習が終わったあとに残る重み行列**がそれである。魔法ではない。

#### 共起行列 → PPMI → SVD

word2vec に入る前に，素朴な方法で同じことをやってみる工程。

1. **共起行列** … 語 × 文脈語の同時出現回数
2. **PPMI**（正の自己相互情報量）… 回数を，偶然の共起に対する超過度に変える。
   負の値は 0 に落とす
3. **SVD**（特異値分解）… 次元を落として密なベクトルにする

Levy & Goldberg (2014) は，word2vec (SGNS) がこの行列分解と数学的に近い関係に
あることを示した。**手で作ってみると，word embedding が魔法ではないことが分かる。**

#### CBOW と skip-gram ★

| | 入力 → 出力 | 特徴 |
|---|---|---|
| **CBOW** | 文脈語 → 中心語 | 速い。高頻度語に強い |
| **Skip-gram** (`sg=1`) | 中心語 → 文脈語 | 遅い。**低頻度語に強い** |

**本授業は skip-gram を既定にする。** 文学コーパスは総語数が数百万語と
小さく，関心のある語（「恋」「自由」「機械」）も必ずしも高頻度ではないため。

#### ハイパーパラメータ ★

| 名前 | 意味 | 影響 |
|---|---|---|
| `window` | 中心語の前後いくつを文脈とするか | **小 (2–3) → 統語的・構文的な類似**（品詞が揃う）／**大 (10–15) → 主題的・連想的な類似**（同じ話題の語） |
| `dim` | word embedding の次元数 | 大きいほど表現力は上がるが，小さいコーパスでは過学習・不安定 |
| `min_count` | この頻度未満の語を捨てる | 低すぎると低頻度語のノイズが入る |
| `sg` | 0=CBOW / 1=skip-gram | 上記 |

**文学の主題分析には大きめの window，文体分析には小さめが向く。**

#### 本パイプラインの既定値 ★

記録は `config/pipeline.yaml` の `word2vec:` と `doc2vec:`。**論文には
この4行をそのまま書く。**

| 項目 | 値 | 理由 |
|---|---|---|
| `dim` | **300** | 語彙が1万を超える規模で近傍が安定する。200 では低頻度語の近傍が揺れた |
| `window` | **3** | **狭くしてある。** 語の統語的な振る舞い（品詞・共起の型）を拾いたいから。ウィンドウを広げると主題の近さが優勢になる |
| `runs` | **10** | シードを変えて10回学習し，近傍の一致（Jaccard）で安定性を見る |
| `seeds` | **11, 22, 33, 44, 55, 66, 77, 88, 99, 111** | 並びをそのまま報告に書く |

doc2vec も同じ水準（dim 300／window 3／同じシードの並び）に揃えてある。
⚠ ただし **PV-DBOW（`dm=0`）では `window` は語ベクトルの学習にしか
効かない。** 揃えてあるのは設定の一貫性のためで，作品ベクトルへの影響は
小さい。

⚠ 既定を変えたら**この表・`pipeline.yaml`・ノートブックの3か所**を
同時に直し，`logs/` に日付つきで写しを残すこと。word embedding の数値は
設定に強く依存するので，設定の記録が無い結果は再現できない。

#### 近傍語 (nearest neighbours)

ある語とコサイン類似度が高い語のリスト。word embedding を点検する第一の道具。

#### t-SNE

高次元のベクトルを2次元に落とす非線形の手法。PCA より局所的なまとまりを
見せるのが得意。⚠ **射影は必ず情報を失う**ので，図は探索の道具として使う。
t-SNE 上の**距離や大域的な配置には意味が無い**ことに注意。

#### 主成分分析と UMAP を並べて比べる ★★（Step 5 §3）

**落とし方は1つではない。** 同じ300語を2つの方法で落として並べる。

| | 何を守ろうとするか | 何を捨てるか |
|---|---|---|
| **主成分分析（PCA）** | **大域**の構造（分散の大きい向き）。線形で，**シードに依存しない** | 局所の細かい近さ |
| **UMAP** | **局所**の近さ（各点の近傍） | 大域の配置・塊どうしの距離・軸の意味 |

目で見るだけでは水掛け論になるので，`proj_quality()` が3つの数を返す。

| 指標 | 何を測るか | ふつう強いのは |
|---|---|---|
| 信頼度（trustworthiness） | 画面で近い点が原空間でも近いか（局所） | UMAP |
| 近傍保存 | 原空間の上位10近傍のうち画面でも上位10に入る語数 | UMAP |
| 順位相関 ρ | 原空間の距離と画面の距離の順位の一致（**大域**） | PCA |

**この表が「方法を選ぶ」ということの中身である。** どちらが上でも
「良い射影」ではない。何を守りたいかで選び，選んだ理由を報告に書く。

⚠ 対話版では**同じ語が左右のどこに来るか**を追える。面ごとに座標系が
違うので，`save_interactive(..., coords=[(x1,y1), (x2,y2)])` と渡す。
渡し忘れると2面めの当たり判定が1面めの座標で置かれ，**指した点と出る語が
食い違う**（`check_interactive.py` の 8a で検査している）。

#### `project()` / `proj_quality()`（共通の助手）

2次元に落とす助手。`project(Xn, how)` の `how` は `'umap'`（既定）／
`'tsne'`／`'auto'`。**`'umap'` は使えなければ止まって理由を出す**
（黙って t-SNE に落ちない）。Step 5 の §3 と §4 が同じ助手を使うので，
UMAP の切り分けの案内も1か所にまとまっている。

#### 安定性 (stability) ★⚠

**乱数シードを変えると近傍語は変わる。**

Antoniak & Mimno (2018) は，小規模コーパスでは word embedding の近傍が実験ごとに
大きく揺れることを示した。本授業では**シードを変えて5回学習し，近傍の一致率を
測る**。

> **一致率が低い語について「意味が変化した」と論じてはいけない。**

これは Step 6 の前提になる手続きである。安定でない語は，どんな通時分析に
かけても結果が乱数を測ることになる。

#### Jaccard 係数

2つの集合の重なりの割合 |A∩B| / |A∪B|。ここでは，シードを変えた2回の学習で
得た**近傍語トップ N の集合**がどれだけ重なるかを測るのに使う。

---

### 確認問題

1. 共起行列＋PPMI＋SVD を先にやる教育的な意味は何か。
2. window を 2 と 15 にしたとき，「恋」の近傍語はどう違うと予想されるか。
3. 本授業が CBOW ではなく skip-gram を既定にする理由は。
4. ある語の近傍が学習のたびに入れ替わる。この語について何が言えて，何が言えないか。

<details>
<summary><b>解答</b>（自分の答えを書いてから開く）</summary>

1. word2vec が「文脈分布から意味を近似する」という同じ原理の実装に
   すぎないと分かるため。Levy & Goldberg (2014) が両者の数学的近さを示している。
2. window 2 なら「愛」「情」など**統語的に同じ位置に立つ語・品詞の揃った語**，
   window 15 なら「手紙」「別れ」など**同じ話題に現れる語**が来やすい。
3. コーパスが小さく（数百万語），関心語が必ずしも高頻度ではないため。
   skip-gram は低頻度語に強い。
4. 言えるのは「この語の word embedding は不安定である」ということだけ。
   意味変化の主張には使えない。安定な語だけを Step 6 の分析対象にする。

# Step 6 通時的 word2vec

> ノートブック: `06_diachronic_word2vec.ipynb`
> スクリプト: `08_word2vec_diachronic.py`

### キーワード

回転不変性 / 直交 Procrustes 変換 / 共通語彙 / 時代スライス / drift /
`--runs` とシードの並び / `--balance` / `--max-per-author` /
シャッフル対照 / KWIC

---

#### 回転不変性 (rotation invariance) ★⚠

word2vec の目的関数は**回転に対して不変**である。すべてのベクトルを同じ
直交行列で回しても，内積（＝コサイン類似度）は変わらない。
したがって**学習のたびに空間全体の向きが変わる**。

> 明治期モデルの「恋」と昭和期モデルの「恋」のコサイン類似度を直接計算しても，
> **それは意味の違いではなく，座標系の違いを測っている。**

これが通時的 word2vec の出発点にある問題である。

#### 直交 Procrustes 変換 (orthogonal Procrustes) ★

2つの空間を，距離構造を保ったまま重ね合わせる方法
（Hamilton, Leskovec & Jurafsky 2016）。

1. 両モデルに共通する語彙を取る
2. その部分行列どうしを最もよく重ねる直交行列 $R$ を求める
   $$R = UV^\top \quad\text{where}\quad U\Sigma V^\top = \mathrm{SVD}(B^\top A)$$
3. **回転だけを許す**ので，語どうしの距離構造は保たれる

⚠ 伸縮や剪断を許すと「意味が近づいた」ように見せかけられてしまう。
**直交行列に限ることが要点**である。

#### 共通語彙 (shared vocabulary)

両スライスに共通して現れる語。アラインメントはこの部分空間の上でしか定義できない。
片方にしか無い語（新語・廃語）はアラインメントの基準には使えないが，アラインメント後の空間に
射影して眺めることはできる。

#### 時代スライス (time slice) ★

コーパスを時代で分割した各区間。**切り方が結果を決める。**

| 時代区分 | 語数 | 判断 |
|---|---:|---|
| 明治前期（〜1886） | 54,035 | 単独では学習不可 |
| 明治中期（1887–1899） | 222,610 | 単独では不安定 |
| 明治後期（1900–1911） | 682,188 | ぎりぎり |
| 大正（1912–1925） | 1,168,853 | 可 |
| 昭和戦前（1926–1944） | 2,556,493 | 可 |
| 昭和戦後（1945–） | 1,366,057 | 可 |

**明治期3区分を合わせても96万語**。そのままでは6スライスに切れない。

- (a) 明治（〜1911）／大正／昭和戦前／昭和戦後 の **4スライス** … 本授業の既定
- (b) 戦前（〜1944）／戦後 の **2スライス** … 最も頑健。確認用
- (c) 増補を待って6スライス

⚠ **スライス数を増やすほど，1スライスあたりの語数が減って word embeddings が
不安定になる。** 細かく切るほど精密になるのではない。逆である。

#### drift（変化量）

アラインメント後の空間で，同じ語のベクトルがスライス間でどれだけ動いたか。
`08_word2vec_diachronic.py` は `semantic_change.csv` に出す。

| 列 | 意味 |
|---|---|
| `drift_first_last` | 最初と最後のスライスの間の距離（**試行の平均**） |
| `drift_sd` | 試行間の標準偏差＝**乱数でどれだけ動くか** |
| `drift_cv` | `drift_sd / drift_first_last`。**0.25 を超えたら解釈に耐えない** |
| `drift_min` / `drift_max` | 試行の最小・最大 |
| `runs` | 何回学習して測ったか |
| `drift_mean_step` | 隣り合うスライス間の距離の平均 |
| `drift_max_step` / `max_step_at` | 最大の段とその時代 |

⚠ **drift 上位語には低頻度語・固有名詞が混じりやすい。**
数値の順位をそのまま「意味変化の順位」と読まないこと。

#### `--runs` とシードの並び ★★

`--runs`（既定 **10**）は，**シードを変えてスライス別モデルを何度学習するか**。
シードの並びは `--seeds`（既定 `11 22 33 44 55 66 77 88 99 111`
＝ `config/pipeline.yaml` の `word2vec.seeds`）。

| 仕掛け | 理由 |
|---|---|
| 全体モデルは1回だけ | 語彙と初期値の基準にしか使わない。いちばん大きいので時間の大半を占める |
| チャンクの割り当ては全試行で同じ | **変えるのは学習の乱数だけ。** 他も一緒に動かすと何の効果か分からない |
| 保存するモデルは第1試行のみ | 10回ぶんは置かない。下流で使うときは「第1試行」と明記する |
| `semantic_change_runs.csv` | 試行ごとの生の値（上位2000語）。**平均だけでは検算できない** |
| `w2v_provenance.json` | 設定と**使ったシードの並び**。シードを書かない結果は再現できない |
| `probe_neighbours.csv` の `jaccard_runs` | 指定語の近傍上位10語が試行間でどれだけ一致するか。**0.3 を下回る行の近傍語は読めない** |

時間は概ね試行回数に比例する。ノートブック（Step 6）は授業用に
`RUNS = 3` にしてあり，**回数を報告に書くこと**を注記してある。
論文用には既定の 10 回で測り直す。

#### `--balance` / `--max-per-author`

統制のための引数。

- `--balance` … 各スライスの語数を最小スライスに合わせる。**語彙量が違うと
  観測される語彙の多様性が変わり，見かけの「変化」が増える**
- `--max-per-author` … スライス内で1作家あたりの語数に上限を設ける。
  昭和戦前が海野十三ばかりなら，測れるのは時代ではなく海野である

#### シャッフル対照 (shuffle control) ★★

**本授業で最も重要な手続き。**

Dubossarsky et al. (2017) は，語をランダムにシャッフルした**偽の時系列**でも
意味変化の「法則」（頻度が高い語ほど変化しない等）が再現されてしまうことを
示した。つまり，観測された「法則」の多くは**word embedding の統計的性質の産物**である。

手続き：**時代ラベルをシャッフルして同じ手順を回す。**

> 本物の変化量が偽の変化量とほとんど変わらなければ，
> 観測された変化は時代効果ではない。

⚠ 対照条件のない「変化を検出した」という主張は，この授業では受け付けない。

#### KWIC (KeyWord In Context)

検索語を中心に前後の文脈を並べて表示する形式。**数値を原文に戻して確かめる
ための道具。** 本パイプラインにはブラウザで使う本式のコンコーダンサがある
（下項「KWIC コンコーダンサ」）。

> **数値だけで論じない。** drift が大きいと出た語は，必ず KWIC で実際の
> 用例を読み，何が起きているかを自分の目で確かめる。

#### KWIC コンコーダンサ ★★

**分析の最後の砦は "back to texts" である。** 頻度表・特徴語・word embedding は
問いを作る道具で，答えは本文にある。そのための道具立て。

| ファイル | 役目 |
|---|---|
| `scripts/15_kwic_index.py` | 索引づくり（`data/tokens/tsv` → `data/kwic/`） |
| `scripts/16_kwic_server.py` | 画面を出すサーバ（標準ライブラリだけ）／書き出し |
| `scripts/kwic_core.py` | 中身（索引と検索）。**ノートブックからも使える** |
| `scripts/kwic_app.html` | 画面1枚（外部の CDN・JS 枠組みを使わない） |
| `scripts/check_kwic.py` | 意味論の検査（下項） |

```bash
python scripts/15_kwic_index.py           # 索引（05 のあと・辞書を替えたら再作成）
python scripts/16_kwic_server.py --open   # 画面（127.0.0.1 のみ）
```

ノートブックからは Step 3 §5.5。表で欲しいときは

```python
from kwic_core import KwicIndex
kwi = KwicIndex(ROOT/'data'/'kwic')
res = kwi.search('汽車', stream='lemma', context=7, sort='year')
show(kwi.to_frame(res), align={'左文脈': 'right', 'キーワード': 'center'})
```

**入力は TSV である。** `tokens_lemma` / `tokens_surface`（空白区切りの列）
には品詞が無く句読点も落ちているので，1行1形態素の TSV から索引を作る。
これで**語彙素と表層形が同じ索引に同居**し，「語彙素で検索して表層形で読む」
ができる。

##### 検索式

| 書き方 | 意味 |
|---|---|
| `汽車` | そのままの一致（選んだ列） |
| `汽車\|電車` | どちらか |
| `乗*` `*車` | 前方・後方一致 |
| `re:^汽.$` | 正規表現（**語彙に**当てる。本文を走査しないので速い） |
| `*` | 任意の1語 |
| `/動詞` | 品詞だけ（大分類の前方一致） |
| `言う/動詞` | 語形と品詞 |
| `L:言う` `S:云ふ` | その項だけ語彙素／表層形（**混ぜられる**） |
| `汽車 に 乗る` | 語の連なり。**文境界は越えない** |

⚠ **語彙に無い語形は「0件」ではなく理由が出る。** 「0件」と「列を間違えた」
「辞書が複合語を切っている」「旧仮名の表記が違う」を区別できないのが，
コンコーダンサのいちばん危ない振る舞いである。

##### 出典と正規化

用例には**時代区分・著者・作品名**（＋初出年・文体）が付く。突合は
0埋めに強いキー（`stem_keys`）で行い，**突合できなかった作品は
「（メタデータ無し）」と画面に出す**（空欄にして誤魔化さない）。

時代区分ごとの分布は**1万語あたりで正規化**して出す。区分ごとに作品数も
語数も違うので，**生のヒット数を時代比較に使ってはいけない。**

##### 共起語

LogDice（既定）・MI・t を併記する。**MI は低頻度語を持ち上げる**ので，
文学コーパスでは固有名詞や誤解析が上位に来やすい。共起2回未満は出さない。

##### 本文へ広げる

用例の行を押すと前後の文が開き（±140語，押せば±400語まで）、
**語にカーソルを当てると 語彙素／品詞／活用形／語種**が出る。
文単位で切るので読める。**作品の境界は越えない。**

##### 由来

画面の下に「索引の入力・辞書名・版・作成時刻・作品数・形態素数」を常に出し，
CSV の1行目と書き出した HTML にも同じことを書く。**どの辞書で切った本文を
読んでいるか分からない用例は，証拠にならない。**

⚠ **索引は 05 を走らせ直したら作り直す。** 辞書を替えれば切り方が変わる。
古い索引のままだと，用例と本文が食い違う。

##### 実装の覚え書き

* 検索は numpy の整数配列を走査する（転置索引を持たない）。**実装が単純な
  ほうが誤りが少ない。** 1000万形態素・語彙素15万種の合成索引での実測:

  | 検索 | ヒット | 時間 |
  |---|---|---|
  | 1語 | 71 | 48 ms |
  | 2語の連なり | — | 58 ms |
  | 正規表現 | 699 | 63 ms |
  | `/動詞`（品詞だけ） | 833,103 | 81 ms |
  | `語*`（語彙のほぼ全部） | 10,000,000 | 595 ms |
  | `/動詞` ＋ 共起語30語 | 833,103 | 810 ms |
  | `語*` を左文脈で並べ替え | 10,000,000 | 2.5 秒 |

* **配列は非圧縮の .npy で書き，mmap で開く**（`data/kwic/arrays/`）。
  圧縮した .npz にすると，1000万形態素の展開に十数秒かかり，
  その間ブラウザからは「サーバに接続できません」に見える。
  非圧縮なら起動は **0.11 秒**。索引は 190 MB ほどになるが `data/` は git の外。
* 何十万件も当たる式のために，集計・並べ替え・共起語は**すべて numpy で
  行う**。とくに
  - 語形の集計は番号の組を整数1つに畳んで `np.unique`
  - 並べ替えは語形を**辞書順の順位**に直して `np.lexsort`
    （文字列を Python で並べ替えると何十万件で数秒かかる）
  - 共起語はずらし幅ごとに一括で拾って `np.bincount`
  これで `語*`（1000万件）が 19 秒から 0.6 秒になった。
* ワイルドカードと正規表現は**語彙**（数十万語）に当ててから位置を引く。
  本文を正規表現で走査しない。
* サーバは `127.0.0.1` のみ。認証の無い簡易サーバなので，学内のネットワークに
  公開しないための仕様である（`--host` で変えられるが，何を公開するかは自分で判断）。
* 画面の `Content-Security-Policy` は `default-src 'none'` で，
  **`connect-src 'self'` を忘れると自分の API も呼べない**。

### 確認問題

1. 時代ごとに学習した2つのモデルの間で，同じ語のコサイン類似度を直接
   計算してはいけないのはなぜか。
2. Procrustes アラインメントで，回転だけを許し伸縮を許さないのはなぜか。
3. 6スライスに細かく切ったほうが精密な通時分析になる，という考えの誤りを指摘してみよう。
4. シャッフル対照で何を確かめるのか。結果が「差が無い」だったら何と書くか。

<details>
<summary><b>解答</b>（自分の答えを書いてから開く）</summary>

1. word2vec の目的関数は回転不変なので，学習ごとに空間の向きが変わる。
   直接計算したコサインは意味の違いではなく**座標系の違い**を測っている。
2. 伸縮や剪断を許すと語どうしの距離構造が変わり，「意味が近づいた」と
   見せかけられるため。直交変換なら距離構造が保たれる。
3. スライスを増やすほど1スライスの語数が減り，word embeddings が不安定になる。
   本コーパスでは明治期3区分を合わせても96万語しかなく，単独では学習できない。
4. 観測された変化量が，**時代ラベルを壊しても同じだけ出るかどうか**。
   差が無ければ「観測された変化は時代効果として支持されない」と書く。
   これは失敗ではなく，正しい否定的所見である。

</details>

#### 文書をベクトルにする3つの道

| 方法 | 長所 | 短所 |
|---|---|---|
| 語頻度ベクトル（BoW / tf-idf） | 解釈しやすい。安定 | 語順・文脈を捨てる |

#### Paragraph Vector (PV) ★

Le & Mikolov (2014)。**文書 ID を追加の「語」として学習に参加させる**。
学習が終わると，その ID に対応するベクトルが文書の表現になる。

| | 対応する word2vec | 性質 |
|---|---|---|
| **PV-DM** (`dm=1`) | CBOW | 語順を一部考慮 |
| **PV-DBOW** (`dm=0`) | skip-gram | 小規模コーパスで**安定しやすい**。本授業の既定 |

#### 語彙のギャラクシー（UMAP / t-SNE の射影）★⚠

300 次元の word embeddings（既定 1万語）を2次元に落として全体を眺める図
（Step 5 §4）。**UMAP**（無ければ t-SNE）で射影する。

色分けは**二重**にしてある。この図の主眼が「文法的な関係と意味的な
関係の両方が同時にモデル化されている」ことを見せることだからである。

| 手がかり | 何を示すか | 値 |
|---|---|---|
| **色** | 文法的なまとまり | 品詞（名詞 `#0072B2`／動詞 `#D55E00`／形容詞 `#009E73`／副詞 `#CC79A7`／助動詞 `#E69F00`／代名詞 `#56B4E9`／**助詞・その他は灰**） |
| **マーカーの形** | 意味・機能のまとまり | `ANCHORS` のカテゴリ（最大11。`tokens_lemma` のときは文語の助動詞・口語の助動詞・人称代名詞の3群が加わる） |

⚠ 助詞を灰色にまとめてあるのは，**散布図で7色は見分けられない**からで
ある（`#F0E442` は明度の帯から外れ，`#666666` は彩度の床を割る）。
凡例で「助詞（n）・その他・不明（m）」と名指しするので，灰色の意味は
曖昧にならない。

見どころは**同じ色の中に別の形の塊がいくつもできている**ところである。
`ANCHORS` を書き換えれば自分の問いのカテゴリで色分けできる。品詞をまたぐ
カテゴリを立てると色がばらけて形だけが揃う——「意味では揃うが文法では
揃わない」カテゴリの見え方である。

⚠ 4色は dataviz の検証器を**全ペアで**通してある（`--pairs all` →
ALL CHECKS PASS）。形容詞と副詞の対は色覚差 7.6 で 6–8 の下限帯に入るので，
**色だけに頼らせない**。マーカーの形・図に直接置くカテゴリ名・表の3つで二重に示す。

⚠ 品詞の取得率が6割を下回るときは**色分けをしない**（`POS_OK`）。
覆えていないのに色分けすると，灰色の意味が「不明」から「その他の品詞」へ
静かにすり替わる。

⚠ **軸に意味は無い。** 上下左右は主成分のような解釈可能な軸ではなく，
**近さだけ**が意味を持つ。その近さも，300 次元の近さを2次元に押し込んだ
結果である。だからこの図は，**射影がどれだけ嘘をついているか**を
一緒に出す約束にしてある。

| 指標 | 何を測るか |
|---|---|
| **信頼度**（trustworthiness） | 2次元で近く見える点が原空間でも近いか。1 に近ければ嘘が少ない |
| **近傍保存** | その語の原空間での上位10近傍のうち，画面上でも上位10近傍に入る語数 |

本コーパスでの一例（dim 200・window 5・語 1,511・UMAP）は
**信頼度 0.82／近傍保存 平均 2.5/10**。つまり**画面で隣にある語の多くは，
本当の近傍ではない。** 対話版で点を指すと原空間の近傍10語へ線が伸びるので，
**線が遠くまで伸びる語**を見れば，その語について2次元の距離を読んでは
いけないことがその場で分かる。

⚠ **上の数値は設定（語数・dim・window）によって変わる**（語数を増やすと
信頼度は下がるのが普通である）。報告には必ず「何語・どの射影・どのシードで
測ったか」を書く。信頼度は O(N²) なので 2,000 語の**無作為標本**で測って
おり，図と HTML にもそう刻まれる。

⚠ 射影の設定（`min_dist`・`n_neighbors`・perplexity）は**作図の設定で
あって分析結果ではない**。締まった塊が出たからクラスタがあるとは言えない。
シードを変えて2回描き，同じ結論が言えるかを確かめること。

⚠ 1万語では**全対類似度行列（10000×10000＝400 MB）を作らない**。
近傍は行を 512 語ずつに切って上位 K だけ残し，画面側は k-d 木で引く。
群内・群外の平均類似度は和のノルムから厳密に出せる（下項）。

#### UMAP のはずが t-SNE になっている ★⚠

`uv add umap-learn` したのに図が t-SNE になることがある。
**原因は UMAP ではなく環境である。** 原因は4つで，どれも見た目は同じ。

| 原因 | 見分け方 | 対処 |
|---|---|---|
| **入れた先とカーネルの環境が違う**（最多） | `import umap` が `ModuleNotFoundError` なのに「入れたはず」 | **カーネルの Python を名指しして入れる**：`uv pip install --python "<sys.executable の値>" umap-learn` → カーネルを再起動 |
| カーネルが別の Python（anaconda3 など） | `sys.executable` が `dh_project/.venv/bin/python` でない | `Kernel → Change Kernel` で `Python (JLit)` に切り替えて再起動。無ければ `bash scripts/00_bootstrap_mac.sh` を実行し直す |
| `umap` という**別パッケージ** | `umap.UMAP` が無いというエラー | `uv remove umap` → `uv add umap-learn`。`umap.__file__` が `umap/umap_.py` を指すこと |
| numba / llvmlite が numpy の版と合わない | `import umap` 自体が例外 | 下の Intel Mac の項の組み合わせで入れ直す |
| **Intel Mac で新しい llvmlite を入れようとした** | インストールが `Failed to build llvmlite` で止まり，`LLVM CMake export states LLVM version is 20, llvmlite only officially supports 22` と出る | 版を固定する（下項） |
| numba がキャッシュを書けない（共用機） | 初回の射影で permission のエラー | `NUMBA_CACHE_DIR` を自分の書ける場所に向ける |

切り分けは **`python3 scripts/check_umap.py`**（下項）。

> uv/pip は最新の `llvmlite 0.49` を**ソースからビルド**しに行き，

#### 凝集度（目で見ずに数える）★

「親族語が固まって見える」のは，**こちらがそう並べたから**かもしれない。
射影の癖でそう見えているだけかもしれない。原空間（300次元）で群内の平均
コサイン類似度を測り，群外との差を見る。差が大きければ，モデルもその群を
1つの塊として見ている。Step 5 §4 では**品詞**（文法）と**カテゴリ**（意味）
の2つの表を並べて出す。**両方で差が出ることが，「文法的な関係と意味的な
関係の両方がモデル化されている」ことの中身である。**

平均は全対行列を作らずに厳密に出せる。群の和を s，語数を n とすると

    Σ_{i,j∈群} x_i·x_j = ‖s‖²  ⇒  群内の平均 = (‖s‖² − n) / (n² − n)

（対角の n 個は自分自身との類似度 1 なので引く。群外との平均は，全体の和
T を使って s·(T − s) / (n(N − n))。）1万語でも記憶を使わない。

本コーパスでの一例（dim 200・window 5・1,511 語。差の大きい順）:
親族・人 +0.227／近代の抽象語 +0.199／自然・季節 +0.157／近代の器物
+0.121／都市・空間 +0.118／身体・知覚 +0.116（全体の平均類似度は +0.121）。
値は設定（dim・window・語数）とカテゴリの立て方で変わるので，報告には
自分の設定で出た表を使うこと。

⚠ **画面上の散らばりと凝集度は別物。** 自然・季節は凝集度が高いのに
画面では最も散っていた（射影がばらけさせている）。逆に画面で固まって
見えるのに凝集度が低ければ，**射影がまとめて見せているだけ**である。
**原空間の数字のほうを信じること。**

#### どの語の列で学習するか — 表層形・語彙素・内容語 ★★

`05_tokenise_unidic.py` は3つの列を書き出す。**どれを使うかは好みではなく，
何を分析の対象とするかの宣言である。**

| 列 | 中身 | 何が起きるか |
|---|---|---|
| `tokens_surface` | 表層形そのまま | 「言う／言った／言ふ／云う」が別の語になる。異なり語数が膨らみ，1語あたりの頻度が下がる |
| `tokens_lemma` | 語彙素・**全品詞** | 活用と表記のゆれを畳む。助詞・助動詞・代名詞も空間に入る |
| `tokens_content` | 語彙素のうち名詞・動詞・形容詞・副詞 | 機能語を落とす。主題的な近さが出やすい |

> **「表層形でないと空間が歪むのではないか」という問いへの答え。**
> 半分は当たっている。ただし歪みの原因は**語彙素に畳んだこと**ではなく，
> **機能語を落としたこと**である。分けて考える。
>
> 1. **機能語を落とすこと**（`content` の問題）。ウィンドウ 3 で
>    「彼 は 汽車 に 乗っ た」を見るとき，助詞を落とすと隣接関係が
>    「彼 汽車 乗る」に変わる。**ウィンドウの意味が変わり，実効的に広くなる。**
>    しかも「が／を／に」対「て／た」という**品詞を見分ける最強の
>    手がかり**が消える。§4 で「文法的な関係もモデル化されている」ことを
>    見せるなら，機能語を落とすのはその手がかりを自ら捨てることになる。
> 2. **語彙素に畳むこと**（`lemma`）。こちらは畳んだほうがよい。
>    1872–1959 のコーパスでは，同じ語が旧字旧仮名・文語活用で
>    **時代ごとに違う表層形**になる。表層形のままだと「時代が下ると語が
>    入れ替わる」という見かけの変化が生じ，**通時比較（Step 6）が壊れる**。
>    低頻度の異形が大量にでき，ベクトルも不安定になる。
>
> したがって対処は `tokens_surface` ではなく **`tokens_lemma`
> （全品詞・語彙素）**。Step 5 §4 のギャラクシーの既定を
> `GAL_STREAM = 'tokens_lemma'` にしたのはこの理由による。

**表層形が要る分析もある。** 文体の指標（旧仮名の比率・活用形の分布・
「ぬ／ず」の使い分け）は表層形でなければ測れない。
`00_extend_metadata.py` が `bungo_per10k` を `tokens_surface` で測るのは
そのためである。**目的で選ぶ。どれかが一般に正しいのではない。**

⚠ **主張する前に数える。** Step 5 §4.0 は3つの列で小さなモデル
（dim 100・10 epochs・1作品 8万語まで）を学習し，異なり語数・低頻度語の
割合・機能語の在否・**品詞の凝集度**・**意味カテゴリの凝集度**を表にする。
列の優劣はその表で決める。

⚠ 表層形の列で学習したときは，**品詞を TSV の `surface` 列で引く**
（`POS_COL`）。語彙素の列で引くと1件も当たらず，図が全部灰色になる
（キーの綴りが合わずに突合が黙って外れるのと同じ型の誤り）。

#### 学習対象の語彙は品詞で絞られている ⚠

`tokens_content` で学習したモデルには **助動詞・助詞・代名詞が無い。**
「なり」「です」「私」を探して見つからないのはモデルの失敗ではなく，
**入力の定義**である。`tokens_lemma` で学習し直せば空間に入る
（ギャラクシーではこのとき文語の助動詞・口語の助動詞・人称代名詞の
3群が凡例に加わる）。Step 6（通時）と Step 8（トピック）が
`tokens_content` を使っているのは，主題の分析では機能語が邪魔になる
からで，**用途が違う**。

#### チャンク単位の学習と作品ベクトル ★

**チャンク単位で学習し，作品ベクトルはその平均とする。**

**なぜか**：作品を1文書として学習すると，長篇ほど学習量が多くなり，
**ベクトルの質が作品長と相関してしまう**（『夜明け前』は『大塩平八郎』の16.5倍）。
Step 3 のチャンク分割がここで効く。

#### カテゴリ効果 (`category_effects.csv`) ★

**同一カテゴリ内の平均類似度**と**異カテゴリ間の平均類似度**の差。
差が大きい軸ほど，document vector がその軸を強く捉えている。

⚠ **作家（`author_ja`）が最大なら要注意。** その document vector が測っているのは
主として「誰が書いたか」であり，時代の主張には統制が要る。

#### 作家効果を取り除く3つの方法 ★

| | 方法 | 性質 |
|---|---|---|
| **(a) 作家中心化** (centering) | 各作家の作品ベクトルから，その作家の重心を引く | 実装が簡単。残差は「その作家にとって，この作品がどう外れているか」 |
| **(b) 層化抽出** | 各作家から同数の作品だけを使う | 情報は減るが交絡は減る |
| **(c) 混合効果モデル** | 作家をランダム効果に入れる（`statsmodels` の `MixedLM`） | 統計的に最も正統 |

本授業では (a) を実装し，**作家効果を除いたあとに時代効果が残るか**を見る。

⚠ 作家中心化すると `author_ja` のカテゴリ効果は**定義上ほぼ 0 になる**。
そこが 0 になったことは成果ではない。見るべきは，そのとき `period` の
効果が残っているかどうかである。

#### 交差検証 (cross-validation)

データを分割し，一部で学習して残りで評価することを繰り返す。
「document vector は時代を予測できるか」を数値で測る。

#### GroupKFold（作家グループ交差検証）★★

**同じ作家の作品が訓練とテストに分かれないように**分割する交差検証。

**なぜ必須か**：普通に分割すると，同じ作家の別作品が訓練側にあるので，
モデルは時代ではなく**作家を覚えて**高い精度を出す。
「時代が当てられた」のではなく「作家が当てられた」だけである。

> **通常の交差検証と作家グループ交差検証の差**こそが，
> その主張がどれだけ作家効果に依存しているかの指標になる。

#### 散布図の色数の上限 ⚠

棒グラフや折れ線なら**隣り合う系列だけが接する**ので，隣どうしが見分け
られれば足りる。**散布図はどの2点も隣り合いうる**ので，全ペアが見分け
られなければならない。この条件は厳しく，色覚の多様性を考慮した既定の
パレットでも **3色が上限**である。

対処：色相は大分類の2つに絞り，**下位の区別はマーカーの形**に持たせる。
形は色とは別の通路なので，色数の上限に縛られない。

# Step 8 トピックモデル（LDA / MALLET）

> ノートブック: `08_topic_modelling.ipynb`
> スクリプト: `10_mallet.py`

### キーワード

LDA / 生成過程 / ディリクレ分布 / α と β / Gibbs サンプリング /
`--optimize-interval` / ストップリスト / トピック数 K / coherence /
exclusivity / lift / トピック分布のエントロピー / ゴミトピック

---

#### LDA (Latent Dirichlet Allocation) ★

文書が次のように作られたと**仮定する**モデル（Blei, Ng & Jordan 2003）。

1. 各トピック $k$ に語の分布 $\phi_k \sim \mathrm{Dir}(\beta)$ がある
2. 各文書 $d$ にトピックの分布 $\theta_d \sim \mathrm{Dir}(\alpha)$ がある
3. 文書の各語について，まず $\theta_d$ からトピック $z$ を選び，
   次に $\phi_z$ から語を選ぶ

**観測できるのは語だけ**なので，$\theta$ と $\phi$ を**逆推定**する。

⚠ この生成過程は**現実の執筆過程の記述ではない**。あくまで計算のための
仮定である。「作家がトピックを選んで書いた」と解釈しないこと。

#### ディリクレ分布 / α と β

「確率分布を生成する確率分布」。α は文書あたりのトピックの散らばり，
β はトピックあたりの語の散らばりを制御する。小さいほど尖る
（少数のトピック／少数の語に集中する）。

#### Gibbs サンプリング

逆推定の手法。語1つ1つについて，他の割り当てを固定したままトピックを
引き直すことを繰り返す。MALLET はこれを使う。

#### MALLET のハイパーパラメータ ★

| 引数 | 意味 | 効果 |
|---|---|---|
| `--num-topics` | トピック数 K | 大きいほど細かい。過大だと解釈不能 |
| `--optimize-interval` | α の最適化 | **必ず有効にする**。トピックの大小を自動調整 |
| `--num-iterations` | 反復回数 | 1000 以上。2000 が安全 |

#### ストップリスト (stop list) ★

分析から除く語の一覧（`config/stopwords_ja.txt`）。

> **トピックモデルの成否の半分はストップリストで決まる。**

本授業では次を除く。

- 形式名詞（事・物・者・訳・筈）
- 指示語・代名詞
- 汎用動詞（為る・有る・居る・成る）
- 汎用形容詞・副詞
- **書誌由来の語**（底本・入力・校正・青空・文庫…）← v1 の混入対策

⚠ **ただし研究の問いによる。** 語りを分析するときは人称代名詞を除いては
いけない。ストップリストは「正しいものが1つある」のではなく，
**問いに対して選ぶもの**である。

#### トピック数 K を選ぶ ★

K は先験的には決まらない。診断指標で当たりをつける。

| 指標 | 意味 | 読み方 |
|---|---|---|
| **coherence** (Mimno et al. 2011) | トピック上位語が実際に共起するか | **負の値。0 に近いほど良い** |
| **exclusivity** | トピック固有の語をどれだけ持つか | 高いほど良い |

⚠ **両者はトレードオフ**。K を増やすと exclusivity は上がるが coherence は
悪化する。**肘（elbow）と解釈可能性の両方で決める。** 指標だけで決めない。

#### トピックを読むときの規律 ★

1. **上位語を見るだけで名づけない。** そのトピックが高い文書を実際に読む。
2. **固有名詞の束はトピックではない。** 特定作家・特定作品の指紋である。
   `exclusivity` が異常に高いトピックはたいていこれ。
3. **「ゴミトピック」を認める。** どのモデルにも解釈不能なトピックが1–2割出る。
   無理に解釈しない。

#### 語を選び直す — 品詞・集中度・散らばり ★（Step 8 §3.5）

05 の `tokens_content` は名詞・動詞・形容詞・副詞をすべて含む。トピックモデルでは

- **固有名詞**（登場人物・地名）は1作品にしか出ないので，トピックが**作品の目印**になる
- **為る・居る・成る**のような非自立の動詞や副詞は，どのトピックの上位にも出る

`18_pos_select.py` は `data/tokens/tsv/` の品詞（UniDic の pos1–pos3）で語を選び直す。
既定（`nva`）は 普通名詞・自立動詞・自立形容詞。加えて次の3つで絞れる。

| 指標 | 定義 | 落とすもの |
|---|---|---|
| 1作品への集中度 | 度数のうち最も多い1作品が占める割合 | 品詞解析が普通名詞と誤った人名（「純一」「山嵐」「法水」） |
| 1作家への集中度 | 度数のうち最も多い1作家が占める割合 | 同じ作家の複数作品に出る人名（宮本百合子の「素子」） |
| dp_in | その語が**いちばん濃い時代の中での** Gries の DP | 少数の作品に固まる bursty な語 |

⚠ **品詞だけでは固有名詞を落とし切れない。** 辞書に無い人名は普通名詞や形状詞と
解析される。集中度で補う。

⚠ 全体の DP ではなく dp_in を使うのは，**時代への偏りは主題として残したい**から
である（Step 4 の `dp_in` と同じ考え方）。全体の DP は「時代に偏る」語も罰する。

#### トピックビューア ★（`19_topic_viewer.py`）

MALLET の結果を1枚の HTML にする（サーバ不要）。上位語を品詞・度数・集中度・
dp_in で絞り，relevance λ で並べ替え，トピックごとに時代別の割合と
割合の大きい作品・作家を見る。複数のモデルを切り替えて比べられる。

**2つの割合を区別すること。** 作品表の「作品内の割合」は P(トピック｜作品)
（その作品の中でこのトピックが占める割合），「トピックに占める割合」は
P(作品｜トピック)（このトピックの重みのうちその作品から来る割合）である。
「A 高校の生徒の半分が野球部」と「野球部員の9割が A 高校」が両立するのと同じで，
向きが逆なので値は一致しない。1作品・1作家に偏ったトピックの警告は後者で出す。
どちらも語の絞り込みでは変わらない。

**relevance**（Sievert & Shirley 2014）＝ λ log p(w|t) ＋ (1−λ) log(p(w|t)/p(w))。
λ=1 はトピック内の確率順，λ を下げるほど**そのトピックに特有の語**が上に来る。

**外来語の表示。** UniDic は外来語の語彙素に原綴を付ける（`テーブル-table`，
`パン-pao`，`ガラス-glas`）。原語が違えば別の語彙素になる（`ロケット-rocket` と
`ロケット-locket`）。ビューアと Step 4 の Excel は片仮名だけを表示し，原綴は
マウスを載せたとき（Excel ではセルのコメント）に出す。原綴は**解析の誤りを
見つける手がかり**でもある：海野十三の SF の「ロケット」は，UniDic では
`ロケット-locket`（ペンダント）と解析されている。本文中でローマ字で書かれた
語（`sport`，`the`）は原綴付きの語彙素とは結び付けられず，別の語として数えられる
（このコーパスでは引用句などに 200 語弱）。

⚠ **ビューアで語を隠すことと，その語を除いて学習し直すことは違う。** 隠した語も
トピックの形成に効いている。カードの「残存」（上位語の確率のうち絞り込み後に
残った割合）が低いトピックは，隠した語でできている。

#### lift（トピック × 時代）

ある時代でそのトピックが期待より何倍多く現れるか。
「どの主題が増え，どの主題が減ったか」を見る指標。

⚠ lift の高いトピックが**固有名詞の束**である場合，それは時代の主題では
なく特定作家の指紋である。`exclusivity` と `coherence` を併せて判断する。

#### トピック分布のエントロピー ★

文書ごとのトピック分布 $\theta_d$ の不確実性。**高いほど，1つの文書が
複数の主題にまたがる。**

これは「近代日本文学におけるトピックの多様化」という本研究の中心的な問いに
直接対応する指標である。

#### エントロピー上昇を読む前の警告 ⚠

上昇を「主題の多様化」と読む前に，次を確かめる。

- **作家構成が時代で変わっていないか。** 昭和期の児童書7点は語彙が平易で
  トピックが散りやすい可能性がある
- **ジャンル構成が変わっていないか。** 探偵小説8点は昭和戦前に集中している
- **チャンク数が時代で違わないか。** Step 6 と同様，バランスを取って再計算する

`audience` と `genre_main` を統制した再集計を必ず行う。

#### 4つの方法の総合 ★

| Step | 方法 | 何を測るか |
|---|---|---|
| 4 | MFW + Delta + PCA | 機能語の使用パターン（＝文体） |
| 6 | 通時 word2vec | 語の意味（文脈分布）の変化 |
| 7 | doc2vec | 作品全体の表現 |
| 8 | LDA | 主題の構成 |

> **4つが一致する所見は強い。一致しない所見は，なぜ違うかを考える材料になる。**

「大正期が文体的に過渡的」が Delta でも doc2vec でも出るなら，それは方法に
依存しない。片方でしか出ないなら，方法の性質（機能語 vs 内容語）に由来する
可能性がある。

4. まだ書けない。作家構成・ジャンル構成・チャンク数が時代で変わっていないかを
   確かめ，`audience` と `genre_main` を統制して再集計してから判断する。

</details>

# 全 Step 共通の道具

ノートブックの冒頭セル（PREAMBLE）で定義され，どの Step でも使える関数。
**自分で書き直す前に，ここにあるかを確かめること。**

#### `run_script()`

`scripts/` のスクリプトを実行し，**標準出力・標準エラー・終了コードを必ず
表示する**。`print(r.stdout or r.stderr)` では，標準出力が空でないときに
エラーの内容が隠れてしまう。

#### `need()` ⚠

必要な入力ファイルが無ければ，**理由と対処を表示して何もしない**。

```
[未実行] data/datasets/chunks_index.csv がありません。
         先に 06_build_datasets.py のセルを実行すること
```

> **これは壊れているのではなく，前の工程がまだ走っていないという意味である。**

#### `save_fig()`

図を **SVG** で `my_work/results/` に書き出す。→ Step 1

ファイル名は `Step1_bungo_kogo.svg` のように **`Step`＋番号**で始める。
`L2_` のような接頭辞は使わない。**`L2` は正則化の L2 ノルムと読めてしまい，
`Step2_normalisation` と `L2 normalisation` が別物だと気づかれない。**

#### `load_meta()`

メタデータを読む。既定で `superseded` / `merged` / `too_short` の行を
**分析から落とす**（落とした件数と作品名を表示する）。
表示用に全件がほしいときは `analysis_only=False`。

#### `work_rows()` / `work_labels()` ★

`work_stem`（`000148_000773` のようなファイル名の語幹）から，
メタデータの行や `夏目漱石『こころ』` という表示名を引く。

⚠ **キーの綴りに注意。** 青空文庫の作品 ID は索引では 0 埋めされていない
（`1743`）が，本パイプラインのファイル名は6桁に 0 埋めしてある
（`000119_001743`）。素朴に連結すると `000119_1743` となり **1件も一致しない**。
辞書は空振りしても例外を出さないので，**誰の何だか分からないまま最後まで
通ってしまう**。`work_rows()` は両方の綴りを登録している。

⚠ **エラーは1つも出ない。** 数字は出るし図も描ける。突合が外れると，
たとえば PCA の図で多くの作品が「初出年不明」の灰色で並び，時代別の集計に
`unknown` という**架空の時代**ができて，他のすべての時代の G² が静かにずれる。
キーは自分で組み立てず，`work_rows()` か `stem_keys()` を通す。そして
**突合できた件数を必ず数えて出す**。数えていない照合は，失敗しても気づけない。

> **`000119_001743` と出されても誰の何だか分からない。**
> 距離の近いペアを見るとき，どの作家のどの作品かが分からなければ，
> 「作家効果か時代効果か」という問いにそもそも答えられない。
> 表示するときは必ず `work_labels()` を通すこと。

#### `attach_meta()` ★

分析スクリプトの出力表に，足りないメタデータの列をメタデータから補う。
出力 CSV の列構成に図の描画が依存すると，スクリプトを書き換えるたびに
図が落ちる。**図の側で「要る列を宣言して取りに行く」**ほうが頑健である。

⚠ **列が無いより，列があって値が空のほうが危ない。** 列が無ければ
`AttributeError` で止まるが，値が空だと**図がそのまま描けてしまう**。
そこで `attach_meta()` は空のセルも補い，補った件数・残った件数を出す。
`work_stem` が1件も突合できないときは `[FATAL]` と言う。

#### `check_stem_keys.py`

`work_stem` のキーを作っている箇所を静的に検査し，**0 埋めを忘れたキー**を
見つける。上の「突合が黙って外れる」誤りを防ぐための道具。

```bash
python3 scripts/check_stem_keys.py
```

注釈や docstring の中の「悪い例」と，`print` の中の表示用の文字列は
検出しない（狼少年にしないため）。

#### `label_points()` ★

散布図の注記を，**重ならない位置だけに置き，引き出し線で点と結ぶ**。
置けなければ省く。

素朴に `ax.annotate()` と書くと，**注目すべき点ほど一箇所に固まる**ので
注記が必ず重なって読めなくなる。かといって重なりを避けてずらすと，
今度は**ずらした先が別の点の隣**になり，読者はそちらの名前だと読む。
図は何のエラーも出さずに出来上がり，**誤った読みだけが残る**。

だから配置はこの順に試す。

1. **点の真上に中央揃えで置く。** これが置ければ線は要らない
2. 塞がっていれば**真上に段を上げる**。x が動かないので左右の順序は保たれる
3. それも塞がっていれば横へずらす。**横のずらし幅は 8〜18 ポイントに
   収める。**30 ポイントも動かすと注記が隣の点の真上に乗り，線で結んでも
   読みにくい。段を重ねるほうを先に試すのはこのためである

2 と 3 で点から離れたものだけを，細い引き出し線で結ぶ。
`leader='arrow'` で矢じりを付けられるが，既定は矢じり無しの線である
（6.5pt の文字に矢じりを付けると，マーカーそのものを覆って点が読めなくなる）。

⚠ **重なり判定の余白は倍率ではなく絶対量で取る。** 1桁の数字は幅 8px
ほどしかないので，8% の余白は 0.6px にしかならず，隣り合う注記が触れる
ほど近くても「重なっていない」と判定される。**`2` と `1` が並んで
「21」と読める**のはこれが原因である。

**引き出し線の交差もほどく。** 線が交差すると，注記の左右の順序が点の
順序と入れ替わる。順位そのものが意味を持つ図（文語標識の上位10件など）
では，2 と 3 が入れ替わって並ぶだけで読み違えられる。交差している2件を
見つけ，位置を入れ替えるか片方を別の候補位置へ動かして解消する（2-opt）。

描くたびに「別の点のほうが近い注記」の件数と，ほどけなかった交差の
件数を報告する。

⚠ **座標と名前は必ず同じ添字で絞り込むこと。** `P[pick,0]` と組むのは
`names[pick]` であって `names` ではない。長さが違えば例外で止まるが，
静的に確かめるには `scripts/check_scatter_labels.py` を使う。

#### 列名の約束 — 割合（0–1）と百分率（0–100）★

出力の列名は，**末尾で尺度が分かる**ように綴り分ける。

| 末尾 | 値の範囲 | 例 |
|---|---|---|
| `_prop` / `_ratio` / `_share` | **0–1**（割合・比率） | `df_all_prop` `bungo_ratio` `top_work_share` |
| `_rate` | 0–1（出現率の意で使う） | `unknown_rate` `aux_rate` |
| `_pct` | **0–100**（百分率） | `types_pct` `tokens_pct`（`14_unknown_profile.py` のみ） |
| `_per10k` / `pm_` | 1万語あたり／100万語あたり | `bungo_per10k` `pm_in` |

なぜ要るか。**`0.15` と `15` を取り違えると，閾値がそのまま 100 倍ずれる。**
`df < 10%` の culling を `df_all_prop >= 0.10` と書くか `>= 10` と書くかは，
列の尺度を知らなければ決められない。列名が答えれば，CSV を表計算ソフトで
開いた人も，半年後の自分も迷わない。

⚠ 列名 `df_all_pct`・`df_in_pct` を見かけたら，それは `df_all_prop`・
`df_in_prop` の旧名である。中身は 0–1 なので per cent は誤称である
（1 が最大値になる量を百分率とは呼べない）。ノートブックの `read_table()` は
旧名を自動で読み替えて知らせるが，**`07_descriptive_stats.py` を走らせ直すのが
正しい**。

#### `check_units.py` ⚠

上の約束を**機械で見張る**。スクリプトを実行せず，AST と正規表現で次を見る。

1. `_pct` という名前なのに `100 *` が無い（＝中身は 0–1 の割合）
2. `_prop` / `_ratio` / `_share` / `_rate` なのに `100 *` がある（＝中身は百分率）
3. 百分率書式 `{x:.1%}`（値を100倍して表示する）を `_pct` の列に当てている
   — **二重に 100 倍**される
4. 0–1 の値に文字の `%` を後ろから付けている — 100 倍し忘れ

命名は「気をつける」では守れない。**数値がずれても例外は出ない**のが単位の
誤りの質であり，`check_stem_keys.py` や `check_script_calls.py` と同じく，
気づけない種類の誤りは機械に見張らせる。

```bash
python3 scripts/check_units.py
python3 scripts/check_units.py --quiet
```

#### `check_csv_encoding.py` ⚠

CSV/TSV が **macOS の Excel で文字化けしない**かを検査する。

macOS の Excel は，BOM の無い UTF-8 の CSV を開くと**日本語を Shift_JIS と
読んで全部化けさせる**。化けるのは表示だけなので，受講生は「スクリプトが
壊れた」と思い，教員は「こちらでは化けない」と答える（Windows の Excel や
Numbers では化けないことがある）。

対策は**両方向**要る。

1. **書くときは BOM 付き**（`encoding='utf-8-sig'`）
2. **読むときも BOM を許す**（同じく `utf-8-sig`）。受講生が Excel で編集して
   保存すると BOM が付く。`utf-8` で読むと最初の列名が `\ufeffauthor_ja` に
   なって**1行も読めない**のに例外は出ず，「マニフェストが空です」という
   無関係なエラーになる

`utf-8-sig` は BOM の無いファイルを読んでも無害なので，**読み書きとも
一律に `utf-8-sig`** でよい。

```bash
# 検査する
python3 scripts/check_csv_encoding.py
# BOM を付け足す
python3 scripts/check_csv_encoding.py --fix
```

#### `14_unknown_profile.py` ★

未知語リストを**種類ごとに分類**し，「目で見てカタカナが多い」という印象を
数字に変える。

| 来るもの | 意味 |
|---|---|
| カタカナ外来語 | **正常**（開いた類。辞書に全部は入らない） |
| 固有名詞らしい漢字列 | **正常** |
| 踊り字の残り | **正規化漏れ**（04 を見直す） |
| 外字マーカの残り | **外字が復元できていない**（03 を見直す） |
| 文語の活用形らしい | 辞書の選択の問題 |

⚠ **種類が変わると未知語率の意味も変わる。** 前処理の失敗が消えて外来語
だけが残った段階では，未知語率は「前処理の質」ではなく**外来語の密度**を
測っている。外来語密度は時代・ジャンルの変数なので，**未知語率の高い作品を
「解析の失敗」と読んではいけなくなる。**

カタカナ表記の揺れ（`ラムプ`／`ランプ`，`ヰスキー`／`ウイスキー`，
`ストツキング`／`ストッキング`）の組も出す。揺れは同じ語を別の型として
数えるので異なり語数を膨らませるが，**まとめるかどうかは研究の問いによる**
——表記の揺れ自体が正書法の近代化の資料でもある。

#### `save_interactive()` ★

同じ図から **SVG（静止版）と HTML（対話版）** を書き出す。

| 出力 | 用途 |
|---|---|
| `<名前>.svg` | 論文・配布用。拡大・加筆が効く |
| `<名前>.html` | 探索用。点にカーソルを近づけると語が出る |

**HTML は SVG を作り直さない。同じ SVG を中に埋め込む。** 別に描き直すと
図が2種類でき，どちらが正かが分からなくなる。注記（`label_points()` で
置いたラベル）もそのまま残る。

点の位置は matplotlib の変換（`ax.transData`）から**図全体に対する割合**
として取り出し，HTML 側では百分率で置く。SVG を `width:100%` で伸縮させても
割合は変わらないので，どの幅でも点と当たり判定が合う。座標の計算が
図と HTML で二重にならないので，**ずれようがない**のが要点である。

設計上の約束（`dataviz` の作法に合わせてある）:

- **最も近い点を拾う。** 直径数ピクセルの点の真上に置くことを要求しない
- **語は `textContent` で入れる。** 語はコーパス由来の任意の文字列なので，
  HTML に文字列連結で差し込まない
- **カーソルが無くても同じ情報に届く。** 点の表を下に付け，
  行にカーソルを乗せると図の点が光る（逆引き）
- **外部の JS ライブラリを使わない。** CDN が塞がれたマシンでも開ける

⚠ 静止版は `bbox_inches='tight'` で余白を詰めるが，埋め込み用は**詰めない**。
詰めると図全体に対する割合とファイルの座標系がずれるためである。

**点が数千を超える図（語彙のギャラクシー）のための約束**

| 仕掛け | 何のため |
|---|---|
| `table_idx=` | 表に載せる点を選ぶ。**当たり判定と検索は全点に効く**ので，表に無い語も指せる。絞ったときは「表は N 件（図の点は M 件）」と HTML に明記する |
| 見出しを1回だけ書く | 全点で見出しが同じなら `keys` として1回書き，点は値の並びだけを持つ |
| 近傍語を書かない | `notes=(見出し, None)` とすると，`links` の先の語を**JS が組む**。同じ語の列を点ごとに書かずに済む |
| `coords=` | **面ごとに座標系が違う**図（主成分分析と UMAP の比較）で，面ごとの座標を渡す。渡し忘れると2面めで**指した点と出る語が食い違う** |
| 地の点のラスタ化 | `rasterized=True`。1万点をベクタで描くと SVG が数十 MB になる |

1万語のギャラクシーで，この3つの省略により HTML は **4.2 MB → 2.0 MB**
になった。壊れると吹き出しが空になるので，`check_interactive.py` で
検査する（上項）。

**由来を図自身に刻む。** `source=` に入力ファイルを渡すと，HTML の末尾に
「入力 ○○.csv（更新 日時）／点 N 個／作図 日時」が入る。入力が
プロジェクトの外（`/tmp` など）にあるときは，赤枠で
**「試験用の入力から作った図である。配布してはいけない」**と出る。

試験用のデータで作った図も，図としては正しく動くので，**中身が偽物であることが
図から分からない**。入力のパスと点の数が図に書いてあれば，取り違えはその場で分かる。

#### `show()` / `grid()` ★

分析結果を**表**として出す道具。`show(df, caption=…, fmt=…)` は
見出しを付け，索引を隠し，数値の列を右寄せにして表示する。
`grid(語の並び, ncol=10)` は長い語の列を n 列の表に畳む。

**一覧は print ではなく表で出すこと。** print には3つの難点がある。

1. 全角の幅のせいで桁が揃わず，数字を縦に比べられない
2. 列に名前が付かないので，あとで見返すと**何の数字か分からない**
3. 並べ替えも絞り込みもできない

列名はそのまま「何を測ったか」の記録になる。`fmt` で単位（`{:.1%}`
`{:,.0f}`）を付ければ，桁の読み違えも防げる。

⚠ **何でも表にするのではない。** 単発の数値・警告・KWIC の前後文脈・
読ませる本文は，文のほうが読みやすい。目安は「列が2つ以上あるか」
「行が並ぶか」。

#### `w_ljust()`

全角を2桁と数えて左詰めする。`f'{s:<26}'` は**文字数**で詰めるので，
日本語の作品名を並べると桁が揃わない。表にしにくいもの（KWIC の
前後文脈など）を print で並べるときに使う。

# 方法論の通奏低音

用語を覚えるより，この5つを言えるようにすること。**最終レポートの
評価軸でもある。**

### 1. 削らず，分離する

削除は不可逆である。v1 の3つの欠陥（重複・外字喪失・奥付混入）はすべて
「要らないものを正規表現で削る」方針から生じた。タグで分離しておけば，
何を数えるかは後段の設定で決められる。 → Step 2

### 2. 決定はすべて記録する

踊り字の扱い・語彙素方針・チャンク長・抽出方法・乱数シード・ストップリスト。
どれも結果に効く。**論文に書けない決定は，していないのと同じである。**
`config/pipeline.yaml` を添付するのはそのため。 → Step 3, 8

### 3. 交絡を疑う

本コーパスは作家・ジャンル・時代・正書法が互いに絡んでいる。
「時代の効果」に見えるものが，実は作家の効果，ジャンルの効果，
底本の正書法の効果であることを常に疑う。 → Step 4, 6, 7, 8

### 4. 対照条件を置く

「変化を検出した」と言うには，**変化が無いはずの条件で同じ手続きを回して
比べる**必要がある。シャッフル対照（Step 6）・グループ交差検証（Step 7）・
安定性検査（Step 5）がそれである。

### 5. 数値は原文に戻して確かめる

drift が大きい語は KWIC で用例を読む。トピックは，そのトピックが高い文書を
実際に読む。**数値だけで論じない。** → Step 6, 8
