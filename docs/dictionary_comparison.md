# 解析辞書の比較 — どの UniDic でコーパスを解析するか

**対象**: `unidic-cwj`（現代書き言葉）と `unidic-kindai-bungo`（近代文語），
および同時に検討すべき他の変種
**道具**: `scripts/12_dict_compare.py`（内在指標）／`scripts/13_pipeline_compare.py`（外在指標）

> ## 結論（2026-09-22 決定・確定）
>
> **本番の辞書は `unidic-novel`（近現代口語小説UniDic v202512）。**
> 4 辞書を 111 点で比べ，未知語率 0.17%（cwj の 3.9 分の 1）かつ平均語長は
> cwj より長い。`unidic-kindai-bungo` は**検算用**に限って使う。
> `cwj` は使わない。判定は §10，記録の場所は §10 の表。
>
> **以下 §1–§9 は，その判定に至る手続きの記録である。**
> 教材としては「辞書をどう選ぶか」の手順そのものが中身であり，
> 結論だけを読んで済ませるところではない。

## 0. 先に言っておくべきこと

### (a) 「どちらが良いか」はコーパス全体では答えが出ない

本コーパスは 1872–1959 年の 101 点で，**文語論説から昭和の口語小説まで**を
含む。`unidic-kindai-bungo` は名前のとおり**近代の文語論説文**のための辞書
である。福沢諭吉『学問のすすめ』・北村透谷『内部生命論』・正岡子規
『歌よみに与ふる書』には合うが，坂口安吾や海野十三の口語小説に合う理由は無い。

したがって問いは「どちらが良いか」ではなく，

> **どの層で，どちらが，どれだけ良いか**

である。`12` と `13` はこの形で答えを出すように作ってある。

### (b) 二択が正しい問いとは限らない

国立国語研究所は近代文語のほかにも変種を配布している。本コーパスの構成
（口語小説が大半・旧仮名が相当数）を踏まえると，**少なくとも次の2つは
候補に入れるべき**である。

| 辞書 | 想定する言語 | 本コーパスでの当たり |
|---|---|---|
| **近現代口語小説UniDic** | 近現代の口語小説 | **本コーパスの主要部分そのもの** |
| **旧仮名口語UniDic** | 旧仮名づかいの口語 | 新字旧仮名・旧字旧仮名の小説 |
| 近代文語UniDic | 近代の文語論説文 | 文語体の論説（10点程度） |
| 現代書き言葉UniDic (cwj) | 現代の書き言葉 | 昭和戦後の作品／基準線 |

`12_dict_compare.py` の `--dict` は何個でも並べられる。**2つで比べる前に，
4つ並べて層別の表を1回出すほうが早い。** どれか1つに絞る判断は，その表を
見てからでよい。

### (c) 版番号に注意

利用者が「unidic-cwj-3.1.x」と呼ぶ版は旧来の採番で，現在 NINJAL が配布して
いるのは**日付ベースの採番**である（`unidic-cwj-202512.zip`,
`unidic-kindai-bungo-v202512.zip`）。さらに `pip install unidic` →
`python -m unidic download` で入るものは**また別の版**である。

> **比較する辞書は同じ入手経路で揃えること。** pip 版と NINJAL 版を混ぜると，
> 測っているのが辞書の違いなのか版の違いなのか分からなくなる。
> 使った版は必ず記録する（`12` は `dict_features.csv` にパスを残す）。

## 1. 比べてよいもの・いけないもの

| | 比較の可否 | 理由 |
|---|---|---|
| 未知語率・平均語長・境界一致率 | **可** | 同じ文字列に対する同じ定義の量 |
| Delta / doc2vec の最近傍一致率 | **可** | 「作家を当てられた率」は同じ土俵の成績 |
| LDA の coherence / exclusivity | **可**（同じ K で） | モデルの当てはまりの指標 |
| 処理時間 | 可 | ただし実用上の判断材料にすぎない |
| **MFW の中身** | **不可** | 語彙素の体系が違う。同じ語が別の見出しになる |
| **特徴語リスト** | **不可** | 同上。「良い語が出た」は比較として成立しない |
| **トピックの上位語** | **不可** | 同上 |
| 語彙数（type 数） | 条件つき | 単位認定が違うので大小に意味は無い。**極端な値の検出**にだけ使う |

論文に「A 辞書のほうが解釈しやすいトピックが出た」と書きたくなるが，
それは**読み手の印象**であって比較ではない。書くなら，同じ K で
coherence / exclusivity がどう違ったかを書き，上位語は**例示**として
両方を並べる。

## 2. 指標と，その落とし穴

### 未知語率 — 低ければ良い，ではない

辞書は未知語を避けるために，**既知の短い単位へ細かく刻む**ことができる。
極端に言えば1字ずつに切れば未知語率は 0 になる。したがって未知語率は
**必ず平均語長・1字語率と並べて**見る。

> 未知語率が下がり，同時に平均語長も下がっていたら，それは
> 「よく解析できた」のではなく「刻んだ」のかもしれない。

### 境界一致率 — 正解が無くても比較はできる

2つの辞書が同じ文字位置で切っているかを Jaccard で測る。正解データが
無いので「どちらが正しい」は言えないが，**どこで判断が分かれたか**は
分かる。`dict_disagreements.csv` に実例が出るので，**必ず目で読む**こと。
文語の助動詞（けり・べし・なり）と複合辞（に-あり／なり）の扱いが
分かれるはずで，そこが文体計量の結果に直接効く。

### 助動詞比率 — 本コーパスでは重要

文語標識（なり・けり・べし・ごとし）は Step 1 の文体分類の基礎である。
**辞書が助動詞をどう立てるかで `bungo_per10k` の値そのものが変わる。**
辞書を替えるなら，`style_class` の再計算が要る（`00_extend_metadata.py`）。

### Delta 最近傍（作家） — 外在指標の本命

同じコーパス・同じ MFW 数で，最近傍が同じ作家である率が高いほど，
その辞書のトークン化は**文体の指紋をよく残している**と言える。
ただし時代の一致率と**並べて**見ること。作家効果と時代効果は交絡する。

### LDA coherence / exclusivity — 同じ K で

K を揃えないと比較にならない。`13` は既定で K=40 に固定する。

## 3. 手順

### 準備

```bash
# NINJAL から各辞書を取得し，/Users/Shared/jlit/ に展開する（admin 権限は不要）
#   unidic-cwj-202512.zip
#   unidic-kindai-bungo-v202512.zip
#   （必要なら 近現代口語小説UniDic・旧仮名口語UniDic も）
ls /Users/Shared/jlit/
```

### 実行 — スクリプトを走らせる（推奨）

**長いコマンドを端末に貼らないこと。** 行の継続（末尾の `\`）が何行も続く
コマンドは貼り間違えやすく，`\\` と2つ重なると zsh は行をそこで終わらせて
`zsh: command not found: --plain` を出す（`docs/00_setup_students.md` §1.0）。
辞書の場所をスクリプトに書いておけば，貼る必要が無い。

```bash
bash scripts/run_dict_compare.sh --check
bash scripts/run_dict_compare.sh
bash scripts/run_dict_compare.sh --full
```

- `--check` … 辞書が読めるかだけを検査して終わる
- 引数なし … 内在指標（速い）
- `--full` … 外在指標まで（重い。辞書1つあたり 15–40 分）

辞書の場所は `scripts/run_dict_compare.sh` の冒頭の `DICTS` を書き換える。
**無い辞書は自動で飛ばし，何個飛ばしたかを報告する**ので，4つ揃うのを
待たずに走らせてよい。

### 内在指標を直接呼ぶ場合

```bash
python3 scripts/12_dict_compare.py \
    --plain data/plain/full \
    --dict cwj=/Users/Shared/jlit/unidic-cwj-202512 \
    --dict kindai=/Users/Shared/jlit/unidic-kindai-bungo-v202512 \
    --meta metadata/corpus_metadata_v3.csv \

```

継続行が不安なときは**1行で書く**（改行が無ければ壊れようがない）。

```bash
python3 scripts/12_dict_compare.py --plain data/plain/full --dict cwj=/Users/Shared/jlit/unidic-cwj-202512 --dict kindai=/Users/Shared/jlit/unidic-kindai-bungo-v202512 --meta metadata/corpus_metadata_v3.csv --out results/dict_compare
```

| `dict_summary.csv` | 全体の未知語率・平均語長・1字語率・助動詞率・秒数 |
| `dict_by_stratum.csv` | 正書法別・文体別・時代別の同じ指標 |
| `dict_by_work.csv` | 作品別 |

## 4. 判定の規則

**先に決めてから走らせること。** 結果を見てから基準を決めると，どちらにでも
結論が書ける。

### 規則 1 — 層ごとに勝者を出す

`dict_by_stratum.csv` の各層で，次の3つを見る。

1. 未知語率が低い
2. かつ平均語長が**下がっていない**（刻んで稼いでいないこと）
3. かつ `dict_disagreements.csv` の実例を読んで，切り方に納得できる

3つを満たせばその層の勝者。**2 が満たされない場合は 1 を採用しない。**

### 規則 2 — 全体の判断は語数で重みづける

層ごとの勝敗を，**作品数ではなく語数**で重みづけて合算する。作品数で数えると
短い文語論説が過大に効く。

### 規則 3 — 外在指標が内在指標と食い違ったら，外在を採る

私たちの目的は解析そのものではなく分析である。未知語率が多少高くても，
Delta の作家識別と LDA の coherence が明確に良いなら，そちらを採る。
**ただし「明確に」の中身を先に決めておくこと。**
目安として，最近傍一致率で 5 ポイント以上，coherence で 0.05 以上の差を
「明確」とする（差がそれ未満なら引き分けとみなし，内在指標で決める）。

### 規則 4 — 引き分けなら cwj を採る

理由は再現性である。cwj は最も広く使われ，第三者が追試しやすい。
**同点なら，珍しいほうではなく標準的なほうを選ぶ。**

## 5. ハイブリッド（層ごとに辞書を替える）について

「文語体は kindai，口語体は cwj」は一見すると最善だが，**強い副作用がある。**

- 語彙素の体系が違うので，**同じ語が層をまたぐと別の見出しになる**。
  `言う`（cwj）と `いふ`（文語辞書）が別語として数えられる
- したがって Delta も doc2vec も LDA も，**層をまたぐ比較が壊れる**。
  「文語体と口語体の距離」は辞書の差を測ることになる
- 本授業・本研究の中心的な問い（言文一致，通時変化）は**まさに層をまたぐ**

結論として，

> **コーパス全体を1つの辞書で解析するのが既定。**
> ハイブリッドを採るなら，**層の内部で完結する分析にのみ**使い，
> 層をまたぐ数値は出さないこと。

どうしても両方使いたい場合は，層ごとに**別々のコーパスとして**報告する
（「文語論説 10 点を kindai で解析した結果」「口語小説 91 点を cwj で
解析した結果」）のが誠実である。

### ただし，近代文語UniDic には別の使い道がある — **検算**

分析用の辞書にはしないが，捨てるのは惜しい。理由は次のとおりである。

`bungo_per10k`（なり・けり・べし・ごとし）は Step 1 の `style_class` を
決め，文語⇄口語の軸そのものを作っている。**この軸が狂うと，本研究の
中心的な問い（言文一致）が根元から狂う。** ところが文語助動詞をどう
単位認定するかは辞書ごとに違い，口語辞書は「けり」「べし」を正しく
助動詞として立てない可能性がある。

そして構成比の皮肉がある。**文語体 13 点は語数では 5.9% しか無いのに，
解釈上はいちばん重い作品群である**（言文一致以前の端を1点で代表して
いる）。語数で重みづける規則 2 では，まさにこの層の精度が軽く扱われる。

そこで，

> **近代文語UniDic は「分析の辞書」ではなく「文語標識の検算」に使う。**

具体的には，A_文語体の 13 点だけを近代文語UniDic で解析し直し，
`bungo_per10k` を再計算して，本番の辞書で出した値と突き合わせる。
値が大きく食い違えば，本番の辞書が文語助動詞を取りこぼしている。

```bash
python3 scripts/12_dict_compare.py --plain data/plain/full --dict main=<本番の辞書> --dict kindai=/Users/Shared/jlit/unidic-kindai-bungo-v202512 --meta metadata/corpus_metadata_v3.csv --out results/dict_bungo_check
```

`dict_by_stratum.csv` の「文体 = A_文語体」の行で **助動詞率（`aux_rate`）**
を比べる。ここが大きく違えば，`dict_disagreements.csv` で
「けり」「べし」「なり」の箇所を読む。**これは辞書の採否ではなく，
指標の妥当性の検査である。** 報告にはそう書く。

## 7. コーパスの構成 — 結果より先に分かること

**判定規則 2 は語数で重みづける。だから，各辞書の「持ち場」がコーパスの
何％を占めるかは，未知語率を1つも測らないうちに決まっている。**
`corpus_metadata_v3.csv` の実測値（分析対象 101 点・延べ 6,211,023 語）:

### 正書法

| | 作品数 | 語数% |
|---|---:|---:|
| 新字新仮名 | 81 | **81.7** |
| 新字旧仮名 | 16 | 15.0 |
| 旧字旧仮名 | 4 | 3.3 |

### 文体

| | 作品数 | 語数% |
|---|---:|---:|
| C_口語体 | 62 | **66.5** |
| B_過渡的文体 | 26 | 27.7 |
| A_文語体 | 13 | **5.9** |

### 形態（上位）

| | 語数% |
|---|---:|
| novel ＋ novella ＋ collection ＋ short-story ＋ diary-novel ＋ cycle | **約 84** |
| treatise ＋ essay（＝近代文語UniDic の設計対象） | **4.6** |

### 正書法 × 文体（語数%）

| | A_文語体 | B_過渡的文体 | C_口語体 |
|---|---:|---:|---:|
| 新字新仮名 | 2.3 | 15.0 | **64.4** |
| 新字旧仮名 | 0.8 | **12.1** | 2.1 |
| 旧字旧仮名 | **2.7** | 0.5 | 0.0 |

### ここから言えること

1. **近代文語UniDic は，全体の辞書にはなりえない。** その設計対象
   （近代の文語論説文）は語数で **4.6%**，文体で見ても A_文語体は **5.9%**
   にすぎない。この層で圧勝しても，語数で重みづけた全体の判断は動かない。
   **これは未知語率を測る前に，構成比だけで決まる。**
2. **近現代口語小説UniDic の持ち場が最大である。** 物語散文が語数で約 84%，
   C_口語体が 66.5%。事前の本命はこれである。
3. **旧仮名は語数で 18.3%**（新字旧仮名 15.0 ＋ 旧字旧仮名 3.3）で，
   近代文語の持ち場より**広い**。しかもその大半は
   「新字旧仮名 × B_過渡的文体」の 12.1% に集まっている。
   **実験の山場は novel と qkana がこの層でどう出るかである。**
4. 近代文語が明確に本拠地と言えるのは「旧字旧仮名 × A_文語体」の **2.7%**
   （4作品・約 17 万語）だけである。

### 予想（走らせる前に固定する）

| 層 | 予想 | 外れたら何を疑うか |
|---|---|---|
| 旧字旧仮名・文語体（2.7%） | kindai が優位 | 正規化（踊り字・外字）が効きすぎて現代語に寄っている可能性 |
| 新字新仮名・口語体（64.4%） | novel が優位，cwj が近い2位 | 素性の並び・単位認定の差を確認する |
| 新字旧仮名・過渡（12.1%） | **novel と qkana が競る** | novel が旧仮名をどこまで収録しているか |
| 全体（語数重み） | **novel が優位** | 構成比を数え直す。刻んで稼いでいないか（平均語長） |

**予想が外れること自体は失敗ではない。** 外れ方が，このコーパスの
どの性質によるものかを説明できれば，それが知見である。

## 8. 既知の技術的な注意

### 素性の並びが辞書によって違う

古文・近代語の UniDic は現代語版と素性の数が違い（17 / 26 / 29），
`orthBase` や `goshu` が無いことがある。無い素性を当てにすると，
`lemma_key` が**黙って表層形に落ちる**。「語彙素で数えたつもりが表層形
だった」という結果になり，未知語率も語彙数も意味が変わる。

`12_dict_compare.py` は最初に素性を調べて `dict_features.csv` に記録し，
足りない素性があれば `[warn]` を出す。**この警告が出たまま先へ進まないこと。**

`05_tokenise_unidic.py` も 2026-09-22 から同じ検査を起動時に行う。
`--lemma-policy mixed` が要る `lemma` / `orthBase` が無い辞書では
**止まる**（続けるには `--lemma-policy surface` を明示するか
`--allow-feature-mismatch`）。黙って表層形に落ちるほうが危険だからである。

### 辞書の混在をどう防ぐか

辞書を替えて 05 を回すとき `--out` を分け忘れると，前の辞書のファイルに
新しい辞書のファイルが混ざる。入力の数は変わらないので件数では気づけず，
エラーも出ない。**混ざった列で数えた頻度表は，もう何を測ったものでもない。**

そこで記録と照合を入れてある。

| 工程 | 何をするか |
|---|---|
| 05 | 解決した辞書名・版・パスを **各 TSV の1行目**と `data/tokens/tokenise_provenance.json` に書く |
| 05 | 本番（`unidic-novel`）以外に落ちたら `[warn]`。`--expect-dict unidic-novel` で停止 |
| 06 | `tokenise_provenance.json` と `config/pipeline.yaml` の `tokenise.dictionary` を突き合わせる。`--strict-dict` で停止 |
| 06 | `data/datasets/dataset_provenance.json` に辞書＋チャンク長＋上限＋種を書く |

辞書を意図して比べるときは `--out` を辞書ごとに分ける
（`13_pipeline_compare.py` は `data/dict_runs/<辞書名>/` に分けて書く）。

### 辞書を替えたらメタデータの実測値も変わる

`bungo_per10k` / `kogo_per10k` / `ttr_x1000` / `style_class` は
トークン列から実測している。辞書を替えたら
`00_extend_metadata.py --remeasure-all` で測り直す必要がある。
**測り直さずに図だけ描き替えると，古い値と新しいトークン列が混ざる。**

### 中間生成物は辞書ごとに分ける

`13_pipeline_compare.py` は `data/dict_runs/<辞書名>/` 以下に分けて書く。
`data/tokens/` を上書きしないので，本番のパイプラインは壊れない。
ディスクは辞書の数だけ要る（1辞書あたり数百 MB）。

## 9. zip が展開できないとき

`unidic-novel-v202512.zip`（近現代口語小説UniDic）のような大きな辞書で
起きやすい。**順に切り分けること。** 「アーカイブユーティリティ」の
エラーメッセージからは原因が読み取れないので，推測で作業しない。

配布元の URL は次のとおり（v202512）。

```
https://clrd.ninjal.ac.jp/unidic_archive/2512/unidic-novel-v202512.zip
```

### 手順 0 — 展開先を Dropbox の外にする（本プロジェクトで最も多い原因）

本プロジェクトのマスター（教員の作業コピー）は `~/Library/CloudStorage/Dropbox/` の下にある
（受講生の作業コピーは `~/Documents/dh_project/JLit_Corpus_2026`）。
**そこに辞書の zip を置いたり展開したりしてはいけない。**

- Dropbox は容量の大きいファイルを**オンラインのみ**の代替ファイルとして
  置くことがある。実体が無いので展開は当然失敗する
- 1 GB の辞書を Dropbox 内に展開すると**数万ファイルの同期**が始まり，
  展開中のファイルが差し替えられて途中で壊れる

zip は `~/Downloads` に置き，展開先は **`/Users/Shared/jlit/`**（同期対象外・
admin 権限不要）にする。本プロジェクトが `/Users/Shared/jlit` を既定に
しているのはこのためである。

```bash
ls -l ~/Downloads/unidic-novel-v202512.zip
mkdir -p /Users/Shared/jlit
```

### 手順 1 — ダウンロードが完結しているか確かめる

**「zip が壊れている」の大半は，途中で切れたダウンロードである。**
サーバが申告する大きさと，手元のファイルの大きさを比べる。

```bash
# サーバ側の大きさ
curl -sIL https://clrd.ninjal.ac.jp/unidic_archive/2512/unidic-novel-v202512.zip \
  | grep -i content-length
# 手元の大きさ
stat -f%z ~/Downloads/unidic-novel-v202512.zip
```

数字が違えば，それが原因である。**手順 2 へ。** 一致していれば整合性を見る。

```bash
unzip -t ~/Downloads/unidic-novel-v202512.zip | tail -5
```

`No errors detected` と出れば zip は無傷で，**問題は展開する側にある**
（手順 1・2 は飛ばして**手順 3 へ**）。

> **`unzip -t` が通った zip を取り直しても無駄である。** ここで切り分けが
> つくので，先に必ず確かめること。1.7 GB を2回落とす前に 10 秒で済む。

### 手順 2 — 取り直す（途中から再開できる）

ブラウザではなく `curl` を使う。`-C -` は**途中から再開**する指定で，
大きいファイルで接続が切れたときに全部を取り直さずに済む。

```bash
cd ~/Downloads
curl -L -C - -O https://clrd.ninjal.ac.jp/unidic_archive/2512/unidic-novel-v202512.zip
unzip -t unidic-novel-v202512.zip | tail -3
```

> **Safari の「安全なファイルを自動的に開く」を切っておくこと。**
> 有効だと，Safari が勝手に展開を始めて zip を消す。途中で失敗すると
> 「中途半端に展開されたフォルダ」だけが残り，原因が分からなくなる。

### 手順 3 — 展開する道具を替える

macOS の「アーカイブユーティリティ」（ダブルクリックで動くもの）は
**最も弱い**。大きな zip や ZIP64 で失敗し，`.cpgz` を作って無限に
往復することがある（zip → cpgz → zip …）。次のどれかを使う。

**空き容量を先に確かめること**（手順 4）。`unidic-novel-v202512.zip` は
1.7 GB で，展開すると 4–6 GB になる。容量が足りないまま走らせると，
途中で止まった中途半端なディレクトリが残る。

```bash
cd /Users/Shared/jlit

# (a) unzip — まずこれ
unzip ~/Downloads/unidic-novel-v202512.zip

# (b) ditto — Apple 純正。アーカイブユーティリティより頑健
ditto -x -k ~/Downloads/unidic-novel-v202512.zip .

# (c) tar（bsdtar）— zip も読める。(a)(b) が駄目でも通ることがある
tar xf ~/Downloads/unidic-novel-v202512.zip

# (d) 最後の手段。Homebrew が使えるなら
#     brew install p7zip
7zz x ~/Downloads/unidic-novel-v202512.zip
```

### 手順 4 — 空き容量を確かめる

辞書は展開すると zip の数倍になる。**容量が足りないとき，
アーカイブユーティリティは「エラー 1」などとだけ言って落ちる。**

```bash
df -h /Users/Shared
```

展開後の大きさの数倍（辞書1つで 2–3 GB 見当）の空きを確保する。
辞書を4つ並べるなら 10 GB 程度は要る。

### 手順 5 — 検疫属性を外す

ダウンロードしたファイルには `com.apple.quarantine` が付く。展開そのものは
通ることが多いが，落ちる場合は外す。

```bash
xattr -d com.apple.quarantine ~/Downloads/unidic-novel-v202512.zip 2>/dev/null
```

### 手順 6 — 展開できたら，使えるかを確かめる

**ここが肝心である。** 展開は途中で失敗しても「それらしいフォルダ」を
残すので，見た目では分からない。解析を始める前に検査する。

```bash
python3 scripts/check_unidic_dir.py /Users/Shared/jlit/unidic-novel-v202512
```

- 必要なファイル（`dicrc` `sys.dic` `unk.dic` `char.bin` `matrix.bin`）の
  有無と大きさ。**0 バイトは途中で切れた展開の典型**
- `fugashi` が実際に読み込めるか
- 素性がいくつあり `lemma` `orthBase` が取れるか

`dicrc` が1段下にあった場合（`unidic-novel-v202512/unidic-novel-v202512/`）も
検出して，`--dicdir` に渡すべき階層を教える。**この1段のずれは，
「辞書が見つからない」という別のエラーになって現れる。**

### それでも展開できない場合

**比較は残りの辞書で進められる。** `--dict` は何個でも並べられるので，
近現代口語小説UniDic を落として

```bash
python3 scripts/12_dict_compare.py --plain data/plain/full \
    --dict cwj=/Users/Shared/jlit/unidic-cwj-202512 \
```

とすればよい。**欠けた辞書があることを報告に書けば，それで十分である。**
無理に揃えるより，揃わなかったことを明記するほうが誠実である。

配布元に問い合わせる場合は，`unzip -t` の出力と，
`curl -sIL` で得た `content-length` と手元のファイルサイズを添えること。
「展開できません」だけでは相手も調べられない。

### 読み取り

**(1) 「刻んで稼いだ」のではない。** 規則1の条件2が最も重要な検査だったが，
結果は逆であった。未知語率の低い3辞書は，**いずれも cwj より平均語長が

`novel` は cwj に対して**未知語率・平均語長・助動詞率の3点すべてで優る**
（厳密優越）。したがって未知語率の差をそのまま採用してよい。

**(2) cwj は落選。** 未知語率が novel の **3.9 倍**，実数で 4.9 万語に対し
1.2 万語である。1872–1959 年のテクストに現代語辞書を当てる以上，構造的な
差であり，版の違いで説明できる幅を超えている。
**規則4（引き分けなら cwj）は発動しない。引き分けではない。**

**(3) novel と qkana は実質的に同じ。** 未知語率の差は 0.02 ポイント，
境界一致率は **0.996**（食い違いは 0.4%）。どちらを選んでも下流の分析は
ほとんど変わらない。**この2つの選択に時間をかける価値は無い。**

**(4) kindai は助動詞率が最も高い**（11.2%，novel より 0.3 ポイント）。
文語助動詞を1語として立てている証拠であり，§5 で述べた**検算の役**に
適することを裏づける。

- `logs/` に今日の `config/pipeline.yaml` の写しを残す

## 11. 指標の意味が変わった — 未知語率は何を測っているか

### 観察（2026-09-22）

`novel` で 05 を回した `unknown_words.csv` は，**大半がカタカナ外来語**で
占められていた。踊り字の残り・外字マーカの残り・文語の活用形は，
目につく範囲では消えている。

### これは何を意味するか

**「検出力が上がった」という言い方は，二通りに読める。**
区別しておく必要がある。

| 読み | 正しいか |
|---|---|
| 未知語をより多く検出するようになった | **誤り。** 未知語率は 0.66% → 0.17% と**下がっている** |
| 未知語リストが，前処理の失敗を拾う網から，**真に辞書に無い語だけを映す鏡**になった | **正しい** |

後者である。カタカナ外来語は**開いた類**で，どの辞書にも全部は入らない。
固有名詞と同じく「残って当然のもの」である。つまり，

> **未知語リストは，欠陥の検出器から，語彙の観察装置へ変わった。**

前処理（踊り字の展開・外字の復元）と辞書の選択（近代の口語小説に
合わせた辞書）が，ともに効いていることの裏づけになる。

### **そして，指標の意味も変わった**

ここが実務上いちばん大事である。未知語率は，もう「前処理の質」を
測っていない。**外来語の密度**を測っている。

そして外来語密度は**時代とジャンルの変数**である。

- 昭和戦前の探偵小説・SF（海野十三・小栗虫太郎）… カタカナが多い
- 明治の文語論説（福沢諭吉・北村透谷）… ほぼ無い

したがって，

> **未知語率の高い作品を「解析の失敗」と読んではいけない。**
> この段階では，未知語率の高さは**その作品が外来語を多く使っている**
> という語彙的事実である。

Step 3 の演習「未知語率で前処理を評価する」は，**この転換点の前と後で
問いが変わる**。ノートブックの説明もそう書き換えてある。

### カタカナ**固有名詞**が上位を占めることの意味

観察はさらに細かく，**未知語リストの上位がカタカナの固有名詞**
（`ハルビン` `マリアナ` `ドストエフスキー`）であった。これは
「カタカナが多い」より強い徴候である。

外国の人名・地名は**二重に開いた類**である——固有名詞であり，かつ
外来語である。どの辞書にも入らない。そして重要なのは，

> **それが1語のまとまりとして未知語に立っていること。**

辞書が無理に既知語へ当てはめず「知らない」と正しく申告した，という
ことである。`ストツキング` を `ストツ` ＋ `キング` と割ってしまえば
どちらも既知になり，未知語率は下がるが**語は失われる**。
上位が固有名詞のまとまりで占められているのは，その当てはめが
起きていない証拠になる。

### ただし，未知語リストは**片側しか映さない**

ここは押さえておく必要がある。未知語リストに出るのは
「辞書に無いと**正しく**判定されたもの」だけである。逆の誤り——
**辞書に無い語を既知の語に無理に当てはめてしまったもの**——は
定義上1件も出ない。

そして**未知語率はその誤りで下がる。** 率だけを見れば
「よく解析できた」ように見えてしまう。

カタカナは，この誤りを機械的に拾える唯一の場所である。外来語は原則
1語として書かれるので，**連続するカタカナが2つ以上のトークンに
割れていたら**，複合語か，さもなければ無理な当てはめである。
漢字の固有名詞（`渋江` → `渋` ＋ `江`）も同じ誤りを起こすが，
正解データが無いと複合語と区別できない。

```bash
python3 scripts/14_unknown_profile.py --unknown data/tokens/unknown_words.csv --tsv data/tokens/tsv
```

`--tsv` を渡すと，未知語の**推定品詞**（固有名詞かどうか）の内訳と，
**割れたカタカナ列**の一覧が出る。`コーヒーカップ` のような正当な
複合語も混じるので人が見て判断する。無理な当てはめが多ければ，
**未知語率の低さは割り引いて読む。**

### 数えて確かめる

「目で見てカタカナが多い」を数字にする。

```bash
python3 scripts/14_unknown_profile.py --unknown data/tokens/unknown_words.csv --report data/tokens/tokenise_report.csv --meta metadata/corpus_metadata_v3.csv --out results/unknown_profile
```

出るもの:

- 種類ごとの割合（カタカナ外来語／固有名詞らしい漢字列／踊り字の残り／
  外字マーカの残り／文語の活用形らしい／ラテン文字・数字／平仮名列／その他）
- **踊り字・外字マーカが 0 種であることの確認**（残っていれば FATAL）
- 未知語率の高い作品を，**時代・下位ジャンルと並べた表**
  （外来語密度として読むため）
- **カタカナ表記の揺れの組**

### カタカナ表記の揺れ — 次に考えるべきこと

戦前の外来語表記は揺れる。`ラムプ`／`ランプ`，`ヰスキー`／`ウイスキー`，
`ストツキング`／`ストッキング`，`サアベル`／`サーベル`。
未知語のまま放置すると**同じ語が別の型として数えられる**。

影響するのは次のとおり。

| 影響 | 中身 |
|---|---|
| 異なり語数・TTR | 膨らむ。語彙の豊かさを過大に見せる |
| word2vec | 同じ語の文脈が分散し，どちらも低頻度で不安定になる |
| LDA | 同じ主題語が別の語として散る |
| 外来語の通時研究 | **表記の揺れ自体が対象**なので，まとめると測れなくなる |

**だから，まとめるかどうかは研究の問いによる。**

- 「外来語の受容の量」を測るなら → まとめる（`ラムプ` と `ランプ` は同じ語）
- 「正書法の近代化」を測るなら → **まとめてはいけない**（揺れが資料である）

どちらにせよ**黙って正規化しないこと。** まとめるなら
`config/pipeline.yaml` に記録し，報告に書く。`14_unknown_profile.py` が
出す組の一覧が，その判断の材料になる。

> **なお，この揺れは踊り字と同じ構造の問題である**（Step 3）。
> 底本の正書法の差が，作家の文体差に見える。違いは，踊り字は
> 規則で展開できるのに対し，**外来語の表記は語ごとに個別**だという点である。
